Binary Indexed Tree

Computer Science

A concise handwritten version of this note is available as a PDF.

Say you have a huge array and you constantly need two operations: compute prefix sums and update individual elements. If you store the raw array, prefix sums cost O(n). If you store prefix sums directly, updates cost O(n). Binary Indexed Tree (BIT) strikes a balance — both operations in O(log n).

The Problem

Given an array x_1, x_2, ..., x_n (where n could be super large), we often want to know the prefix sum Z_k = x_1 + ... + x_k.

Two naive approaches:

  • Store the original array: getting Z_k requires summing k elements — O(n)
  • Store the prefix sum array directly: getting Z_k is O(1), but updating any x_k requires updating all subsequent prefix sums — O(n)

BIT gives us O(log n) for both.

How BIT Stores Values

Instead of storing the original array x_1, ..., x_n, BIT builds a new array y_1, ..., y_n where each y_i stores a partial sum. The key idea is that how many elements y_i covers depends on the binary representation of i:

  • If i is odd: y_i = x_i (just that single element)
  • If i is even but not a power of 2: y_i = x_i + x_{i-1} (covers 2 elements)
  • If i is a power of 2 (i.e. i = 2^k): y_i = x_1 + ... + x_i (covers all elements up to i)

More precisely, y_i covers 2^(number of trailing zeros in binary of i) elements ending at position i.

Operations

1. Construct a BIT: O(n log n)

To add a new value x_{n+1} into the BIT:

  • If n+1 is odd: y_{n+1} = x_{n+1} — O(1)
  • If n+1 is even but not a power of 2: y_{n+1} = x_{n+1} + x_n — O(1)
  • If n+1 = 2^k: y_{n+1} = x_{n+1} + x_n + y_{n-1} + y_{n-3} + ... — O(log n)

2. Search (prefix sum query): O(log n)

To compute Z_i = x_1 + ... + x_i, we sum up a chain of y values by repeatedly stripping the lowest set bit from i:

  • If i = 2^k: Z_i = y_i — O(1), the whole prefix is stored directly
  • If i is even (not power of 2): Z_i = y_i + y_{i-2} + ... + y_j
  • If i is odd: Z_i = y_i + y_{i-1} + y_{i-3} + ... + y_j

In all cases, we hop at most O(log n) times.

3. Update: O(log n)

If we want to update x_i, we need to update all y values that include x_i in their partial sum. This propagates upward through the tree, affecting at most O(log n) entries.

The Lowest Set Bit Trick

To efficiently jump between indices for build, search, and update, we need to find and remove the lowest set bit (LSB) of an index. There's a beautiful bit manipulation trick for this: index & (-index) gives you the lowest set bit.

Here's why it works. Say we have 8 bits:

7  -> 00000111
-7 -> 11111000 + 1 -> 11111001
7 & -7 -> 00000001  (the last 1 in 7)

6  -> 00000110
-6 -> 11111001 + 1 -> 11111010
6 & -6 -> 00000010  (the last 1 in 6)

This works because negation in two's complement flips all bits and adds 1, which propagates through all the trailing zeros and flips the lowest 1 — making it the only bit that aligns between the original and its negation.

For prefix sum queries, we repeatedly subtract the LSB: i -= i & (-i). For updates, we repeatedly add the LSB: i += i & (-i).

def prefix_sum(bit, i):
    s = 0
    while i > 0:
        s += bit[i]
        i -= i & (-i)  # remove lowest set bit
    return s

def update(bit, i, delta, n):
    while i <= n:
        bit[i] += delta
        i += i & (-i)  # add lowest set bit

For example, to get Z_7: we need y_7, y_6, and y_4. In binary: 7 is 111, strip LSB to get 6 (110), strip LSB to get 4 (100), strip LSB to get 0 — done. Three hops, three values summed.
