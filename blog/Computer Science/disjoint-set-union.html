Disjoint Set Union

Computer Science

A concise handwritten version of this note is available as a PDF.

Imagine we have a map with many different locations where edges mean two locations are connected — you can commute between them. The question is: can we drive from location A to location B?

    Location 3
   /           \
Location 1     Location 4
   \           /        \
  Location 2        Location 6 --- Location 8
       \           /
      Location 7

The Naive Solution

Intuitive approach: Use breadth-first search (BFS) or depth-first search (DFS) to check if A and B are connected.

Problem: Time complexity is O(n), where n is the sample size (different locations). If we ask the question many times, it becomes very slow.

Better Solution: Disjoint Set Union (DSU)

Here's the key insight: to check if location A and B are connected, we don't actually need to find a path connecting A and B. We only need to find at least one location connecting to both A and B.

Speedup: Time complexity O(1) — nearly constant time per query!

How DSU Works

Initialization

We initialize sets, each set with its root initialized as the location itself:

Location 1    Location 2    ...    Location n

Set 1: root → location 1    Set 2: root → location 2    ...    Set n: root → location n
Size: 1                      Size: 1                     ...    Size: 1

Initially, every location is its own root — each forms a singleton set of size 1.

Union

Now we check all connected locations. If location A and location B are connected:

  1. Find the root of the set where location A is in — say root = i, Set = Sᵢ
  2. Find the root of the set where location B is in — say root = j, Set = Sⱼ
  3. Check if they're in the same set:
    • If i == j, A and B are already in the same set — nothing to do
    • If i ≠ j, they're in different sets — we union the two sets

How to union efficiently: We can make i the root of j, but there's a smarter way. Always attach the smaller set to the larger set:

if Size(Sᵢ) ≤ Size(Sⱼ):
    make j the root of i
else:
    make i the root of j

This keeps the tree balanced and prevents degenerate chains. Attaching small to large is more efficient!

Find

Given a location, find the root of the set it's connected to. The simplest version just follows parent pointers upward until we reach a node whose parent is itself — that's the root.

But we can do better with path compression.

Path Compression

Here's the clever optimization: when we find the root of a node, we can compress the path by connecting all nodes in the path directly to the root.

Visualize this:

Before compression:           After compression:
        root                          root
       /  \                          / | | \
      2    3            →           2  3 4  5
     /
    4
   /
  5

The next time we query any of these nodes, we reach the root in one hop instead of traversing the whole chain. This dramatically speeds up future queries.

Computational Complexity

Find: O(α(n)) ≈ O(1)

It can be shown that if we:

  • Connect the set with smaller size to the larger set (as in the union step), and
  • Compress the path (as in the find step)

Then performing the find function once takes O(α(n)) amortized time, where α is the inverse Ackermann function. This is mathematically almost O(1) — for all practical purposes, it's constant time.

The inverse Ackermann function grows so slowly that α(n) ≤ 4 for any n you'll encounter in practice. Even if n is the number of atoms in the universe, α(n) is still less than 5.

Union: O(1)

Union essentially performs two finds, and then attaches the smaller set to the larger set. So it's also O(1) amortized.

Building DSU from Scratch: O(n + e)

To build the DSU from scratch given:

  • n nodes — O(n) to initialize
  • e edges — perform e union operations

Total time complexity: O(n + e)

Implementation

Here's a clean Python implementation:

class DSU:
    def __init__(self, n):
        self.parent = list(range(n))  # each node is its own parent
        self.size = [1] * n           # all sets start with size 1

    def find(self, x):
        # Find root with path compression
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])  # compress path
        return self.parent[x]

    def union(self, x, y):
        # Union by size
        root_x = self.find(x)
        root_y = self.find(y)

        if root_x == root_y:
            return  # already in same set

        # Attach smaller to larger
        if self.size[root_x] < self.size[root_y]:
            self.parent[root_x] = root_y
            self.size[root_y] += self.size[root_x]
        else:
            self.parent[root_y] = root_x
            self.size[root_x] += self.size[root_y]

    def connected(self, x, y):
        # Check if x and y are in the same set
        return self.find(x) == self.find(y)

Example Usage

Let's solve the original problem — checking if locations are connected:

# Initialize DSU for 8 locations (indexed 0-7)
dsu = DSU(8)

# Add edges from the graph
edges = [(0, 1), (1, 2), (0, 2), (2, 6), (3, 4), (4, 5), (3, 5)]
for a, b in edges:
    dsu.union(a, b)

# Query: can we drive from location 0 to location 6?
print(dsu.connected(0, 6))  # True

# Query: can we drive from location 0 to location 7?
print(dsu.connected(0, 7))  # False

Each query takes O(1) time — no matter how many times we ask!

Common Applications

DSU shows up everywhere in computer science:

  • Kruskal's MST algorithm — detecting cycles while building the minimum spanning tree
  • Network connectivity — checking if nodes are in the same connected component
  • Image segmentation — grouping pixels into regions
  • Least common ancestor — offline LCA queries in trees
  • Dynamic connectivity — maintaining connectivity as edges are added

Summary

  • Disjoint Set Union (DSU) solves the connectivity problem in nearly O(1) time per query
  • The key optimizations are union by size and path compression
  • With both optimizations, each operation takes O(α(n)) ≈ O(1) amortized time
  • Building DSU from scratch takes O(n + e) for n nodes and e edges
  • The inverse Ackermann function α(n) is so slow-growing that it's effectively constant for any practical input

This is one of those beautiful algorithms where two simple tricks — attach small to large, and flatten paths as you go — combine to give you something that's theoretically complex but practically constant time.
