Learning to Rank Algorithms

Machine Learning

A concise handwritten version of this note is available as a PDF.

Learning to rank is to learn how to optimally order a list of items based on their relevance to a specific context (e.g. a search query or a user profile). There are mainly three types of losses: pointwise loss, pairwise loss, and listwise loss. Here we cover each of them and consider how to evaluate the results.

Pointwise Loss

The data looks like: for query q_i, documents D_i,1, ..., D_i,K_i with scores S_i,1, ..., S_i,K_i (the rank of them, K_i to 1, top to bottom).

Depending on whether the label is a real score or a binary relevance judgment, the loss is either squared error or a classification loss:

L_pointwise = Σ_{i=1}^n Σ_{j=1}^{K_i} ( f_θ(q_i, D_i,j) - S_i,j )²

L_pointwise = -Σ_{i=1}^n Σ_{j=1}^{K_i} 1(S_i,j = 1) log( sigmoid( f_θ(q_i, D_i,j) ) )

Pros:

  1. Very easy to train.
  2. Absolute scores can be useful, e.g. the probability of a user click, conversion probability.

Cons:

  1. Position agnostic. If the real rank is 100 (top) and the prediction is 80, versus the real rank is 1 (bottom) and the prediction is 21, both have the same loss. However, getting the top ranking correct matters more.
  2. Query imbalance problem. If a query is general, it could have more candidate documents, so K_i is large and it dominates the loss. On the other hand, the order for a general query is less important. We could try to mitigate this, e.g. scale the score by the number of documents.
  3. Ignoring comparison. Minimizing the total squared error for each document independently does not guarantee the relative order between two documents comes out correct -- it's possible to end up with a set of predictions with a smaller total loss that gets a pair of documents' relative order wrong, while a set with a larger total loss gets that pair's order right. The target we actually care about is the comparison, not the total loss.

Pairwise Loss

The data now looks like: for query q_i, documents D_i,1 and D_i,2 with S_i,1 > S_i,2 -- no need to know the exact scores.

L_pairwise = Σ_{S_i,1 > S_i,2} log( sigmoid( f_θ(q_i, D_i,1) - f_θ(q_i, D_i,2) ) )

Training: one batch (Q_i, D_i,1), ..., (Q_i, D_i,K) (K could be 2, or larger) goes through the model f_θ to get scores ŝ = ( f_θ(q_i,D_i,1), ..., f_θ(q_i,D_i,K) ), then we compute the loss for all K(K-1) pairs (broadcasting ŝ against itself). To stabilize the gradient, one batch will normally include several queries and their corresponding documents.

Pros:

  1. The model focuses on the actual goal: we care about the comparison between each document given the query.
  2. Practically, it is easier to get pairwise labels (it's easier to compare two things than to rank a whole list of things for a human).

Cons:

  1. If K is large, the loss function takes longer to compute.
  2. It is still position blind.
  3. The query imbalance problem persists (can scale by K(K-1)/2).

Listwise Loss

The data is the same as pointwise: query q_i, documents D_i,1, ..., D_i,K_i, scores S_i,1, ..., S_i,K_i. Compute the probability of each document being ranked at the top.

Predicted probability:

p̂_θ(D_i,j ranked at the top) = exp( f_θ(q_i, D_i,j) ) / Σ_{j'=1}^{K_i} exp( f_θ(q_i, D_i,j') )

The real probability of each document ranked at the top:

p(D_i,j ranked at the top) = exp(S_i,j) / Σ_{j'=1}^{K_i} exp(S_i,j')

Then the loss is the cross-entropy between the true and predicted distributions:

L_listwise = -Σ_{i} Σ_{j} p(D_i,j) log( p̂_θ(D_i,j) )

Training: a batch (Q_i, D_i,1), ..., (Q_i, D_i,K) goes through the model f_θ to get ŝ, then we compute the cross-entropy loss.

Pros: it considers the rank of all documents in the query simultaneously, and solves the position blindness problem of the pointwise and pairwise approaches.

Cons: it will focus heavily on the top 1. If there are 100 documents, the top document takes weight exp(100) / Σ_{i=1}^{100} exp(i) and the loss has bad quality for top 2, top 3, etc.
