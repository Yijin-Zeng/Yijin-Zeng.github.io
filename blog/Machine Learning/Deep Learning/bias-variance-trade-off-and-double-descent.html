Bias-Variance Trade-off and Double Descent

Machine Learning

A concise handwritten version of this note is available as a PDF.

Given enough capacity, a neural network can fit its training data perfectly -- every point, zero training error. That alone says nothing about how well it generalizes to a test set. Generalization error can be decomposed into exactly three parts: inherent noise, bias, and variance.

Where Test Error Comes From: Three Pieces

Suppose the data is generated as:

y = f(x) + ε

where f(x) is the generating function -- the true function we want to learn -- and ε is inherent noise with variance σ². For a fitted model f̂(x; D) trained on dataset D, the generalization error breaks into:

  • Inherent noise: comes from the data itself. Even if we fit the generating function perfectly, this error cannot be reduced.
  • Bias: the difference between the expected prediction ED[f̂(x; D)] and the underlying real value f(x).
  • Variance: the variance of predictions given different training sets. Same x, different D, different answer.

Deriving the Decomposition

The expected test error at a point x, averaging over both the training set D and the noise ε:

E_{D,ε}[(f̂(x;D) - y)²]
  = E_{D,ε}[(f̂(x;D) - f(x) - ε)²]
  = E_{D,ε}[(f̂(x;D) - f(x))² + ε² + 2ε(f̂(x;D) - f(x))]
  = E_D[(f̂(x;D) - f(x))²] + E[ε²] + 0       ← cross term drops: E[ε] = 0

Now add and subtract the expected prediction ED[f̂(x;D)] inside the square:

E_D[(f̂(x;D) - E_D[f̂(x;D)] + E_D[f̂(x;D)] - f(x))²] + σ²

  = E_D[(f̂(x;D) - E_D[f̂(x;D)])²]              ← variance
  + (f(x) - E_D[f̂(x;D)])²                       ← bias²
  + E_D[2(f̂(x;D) - E_D[f̂(x;D)])(E_D[f̂(x;D)] - f(x))]   ← = 0
  + σ²                                            ← inherent noise

The cross term vanishes for the same reason as before (ED[f̂ - EDf̂] = 0), leaving:

Expected test error = Var_D(f̂(x;D)) + (f(x) - E_D[f̂(x;D)])² + σ²
                    =    variance    +        bias²          + noise

Two cross terms, both zero, and the decomposition falls out. Nothing beyond "add and subtract the mean," used twice.

Can we estimate the three pieces in practice?

Given enough data -- as many samples as we want -- is it possible to decompose a model's actual prediction error into variance, bias, and inherent noise? Variance is easy: sample the training data randomly, refit the model, and estimate the variance of its predictions directly. The hard part is separating bias from inherent noise, since they're glued together in what's left.

The trick is to consider a model with zero bias by construction -- one that simply predicts y, the data itself. Its error contains only variance and inherent noise. Since we can already estimate its variance by resampling, the inherent noise falls out by subtraction. From there, subtracting the inherent noise (and variance) from any other model's error leaves its bias.

The Classical Picture: A Bias-Variance Trade-off Curve

The inherent noise can't be reduced, so we want a model with low bias and low variance. This is hard because of the famous trade-off: as model complexity grows, bias falls but variance rises.

So we can't just push model complexity as high as possible and expect a good result. The key is to strike a balance between bias and variance. Common methods:

  • To decrease bias: increase model complexity, or choose a correct model class in the first place -- a linear model can't fit an exponential function no matter how much data you feed it.
  • To decrease variance: increase training data size, decrease model complexity, add regularization, or use an ensemble method -- random forests are the standard example: each tree may keep or even increase bias, but averaging decreases variance.

The Curve Is Incomplete

It turns out the bias-variance figure above is incomplete. If we keep increasing model complexity -- say, to the point where the model has more parameters than training data -- we can observe a phenomenon known as double descent: test error rises through the usual overfitting regime, but then drops again, sometimes to a lower point than the previous sweet spot.

Three phases, each dominated by a different force:

  • Phase I (underfitting): bias decrease dominates -- test error falls.
  • Phase II (overfitting): variance increase dominates -- test error rises. This is where the classical picture stops.
  • Phase III (over-parameterized): variance decrease dominates -- test error falls again.

Why Does Variance Come Back Down?

One explanation: once the number of parameters exceeds the number of training samples, the model has passed through (interpolated) all the training instances -- training error is zero. Any change in the fitted function can then only happen between training points, since the points themselves are already fixed. The model has the freedom to choose how it connects the dots, and it tends to choose a smooth interpolation between them, which keeps predictions stable across different training sets.

So why does the model choose to smooth the path when the training error is already zero and nothing forces it to? The likely cause is the explicit and implicit regularization built into modern training -- SGD, dropout, L2 norm penalties, and so on. This is still an active area of explanation rather than a fully settled one.

Worth keeping in mind: in phase III the model is still overfitting in the technical sense -- there's still a gap between training loss and validation loss. It just generalizes better than the models in the middle of the classical overfitting zone did.

Summary

  • Generalization error decomposes as variance + bias² + inherent noise, derived by adding and subtracting the mean twice.
  • Inherent noise is the floor; the classical game is trading bias against variance and finding the sweet point on the trade-off curve.
  • The classical curve is incomplete: push model complexity past the point where parameters outnumber training data, and test error can descend a second time -- this is double descent.
  • Mechanism: an interpolating model (zero training error) can only vary between training points, and implicit/explicit regularization pushes it toward a smooth interpolation there -- lower variance despite far more capacity.
  • The model in phase III is still technically overfitting -- there's still a train/validation gap -- it just generalizes better than the models before it.
