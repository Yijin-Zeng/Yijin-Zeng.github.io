Bias-Variance Trade-off and Double Descent

Machine Learning

A concise handwritten version of this note is available as a PDF.

Give a neural network enough capacity and it will fit your training data perfectly -- every single point, zero training error. And yet modern LLMs, which are massively over-parameterized (often with far more parameters than training examples), generalize remarkably well. If you took a classical statistics course, this should bother you. It bothered me. The classical theory says a model that interpolates every training point should be a disaster on test data. So why isn't it?

To answer that, we first need the classical story: where does generalization error actually come from?

Where Test Error Comes From: Three Pieces

Suppose the data is generated as:

y = f(x) + ε

where f(x) is the generating function (the true function we want to learn) and ε is inherent noise with variance σ². The generalization error of a fitted model f̂(x; D) (trained on dataset D) decomposes into exactly three parts:

  • Inherent noise: comes from the data itself. Even if we fit f perfectly, this error cannot be reduced. It's the floor.
  • Bias: the difference between the expected prediction ED[f̂(x; D)] and the underlying real value f(x). How wrong are we on average?
  • Variance: how much predictions wiggle when we retrain on different training sets. Same x, different D, different answer.

The Derivation (It's Shorter Than You'd Think)

The expected test error at a point x, averaging over both the training set D and the noise ε:

E_{D,ε}[(f̂(x;D) - y)²]
  = E_{D,ε}[(f̂(x;D) - f(x) - ε)²]
  = E_{D,ε}[(f̂(x;D) - f(x))² + ε² + 2ε(f̂(x;D) - f(x))]
  = E_D[(f̂(x;D) - f(x))²] + E[ε²] + 0       ← cross term dies: E[ε] = 0

Now the classic trick: add and subtract the expected prediction ED[f̂(x;D)] inside the square.

E_D[(f̂(x;D) - E_D[f̂(x;D)] + E_D[f̂(x;D)] - f(x))²] + σ²

  = E_D[(f̂(x;D) - E_D[f̂(x;D)])²]              ← variance
  + (f(x) - E_D[f̂(x;D)])²                       ← bias²
  + E_D[2(f̂(x;D) - E_D[f̂(x;D)])(E_D[f̂(x;D)] - f(x))]   ← = 0
  + σ²                                            ← inherent noise

The cross term vanishes again (ED[f̂ - EDf̂] = 0), and we're left with:

Expected test error = Var_D(f̂(x;D)) + (f(x) - E_D[f̂(x;D)])² + σ²
                    =    variance    +        bias²          + noise

Two cross terms, both zero, and the whole decomposition falls out. I find it satisfying that something this fundamental needs nothing beyond "add and subtract the mean".

A side question I like: can you estimate the three pieces in practice?

Given enough data (as many as we want), is it possible to decompose a model's actual prediction error into variance, bias, and inherent noise? Variance is easy: randomly resample the training data, refit the model each time, and estimate the variance of the predictions directly. The hard part is splitting the remainder into bias and inherent noise -- they're glued together in the error.

The trick: consider a model that always has zero bias -- a model that simply predicts y, the data itself. Its error contains only variance and inherent noise, and since we can estimate its variance by resampling, the inherent noise falls out. Subtract that from any other model's error and the bias is what's left. I thought this was a neat move when I first saw it.

The Classical Picture: A U-Shaped Curve

The inherent noise cannot be reduced, so all we can do is find a model with low bias and low variance. And this is hard, because of the famous trade-off: as model complexity grows, bias falls but variance rises.

error
  │\
  │ \  bias + variance
  │  \      _____/
  │   \    /
  │    \__/  ← sweet spot (set model complexity here)
  │  bias↓      variance↑
  └──────────────────────→ model complexity
   underfitting | overfitting

So we cannot simply crank model complexity to the sky and expect a good result. The key is to strike the balance. The standard toolbox:

  • To decrease bias: increase model complexity, or choose a correct model class in the first place (a linear model will never fit an exponential function, no matter how much data you feed it).
  • To decrease variance: get more training data, decrease model complexity, add regularization, or use ensembles -- random forests are a nice example: each tree may keep or even increase bias, but averaging slashes the variance.

Except... The Figure Is Incomplete

Here's the part that genuinely surprised me when I first learned it. If we keep increasing model complexity past the classical overfitting regime -- say, to the point where the model has more parameters than training examples -- the test error can come back down. And not just down: it can drop below the previous lowest point of the classical U-curve. This is double descent.

test
error │\
      │ \        /\
      │  \      /  \
      │   \____/    \_____
      │      ↑        ↑   ‾‾── keeps improving
      │   sweet     peak near
      │   spot    interpolation
      └────────────────────────→ model complexity
      phase I | phase II | phase III
      (under- | (over-   | (over-
       fitting)| fitting) |  parameterized)

Three phases, each dominated by a different force:

  • Phase I (underfitting): bias decrease dominates. Test error falls.
  • Phase II (overfitting): variance increase dominates. Test error rises -- this is where the classical picture stops.
  • Phase III (over-parameterized): variance decrease dominates. Test error falls again.

Why Does Variance Come Back Down?

One explanation, and the one I find most intuitive: once parameters outnumber training samples, the model has passed through (i.e. interpolated) all the training instances. Training error is exactly zero. So any change in the fitted function can only happen between the training points -- the model now has the freedom to choose how it connects the dots. And it turns out the model tends to choose a smooth interpolation between training points, which keeps predictions stable across different training sets. Smooth interpolation means low variance.

Which raises a new question: why does the model choose to smooth the path, when the training error is already zero and nothing in the loss forces it to? The suspects are all the explicit and implicit regularization baked into modern training -- SGD itself, dropout, L2 norm penalties, and so on. SGD in particular seems to have an implicit preference for low-norm, smooth solutions. Honestly, "why interpolating models are smooth" is still an active research question, so I wouldn't call this case closed.

One caveat worth keeping: in phase III the model is still overfitting in the usual sense -- there's a visible gap between training loss (zero) and validation loss. It just generalizes better than the smaller overfit models did. Double descent doesn't abolish overfitting; it says the gap can shrink again as you go bigger.

Summary

  • Expected test error = variance + bias² + inherent noise -- and the derivation is just "add and subtract the mean" twice.
  • Noise is the floor; the game is trading bias against variance. Classical answer: find the sweet spot on the U-curve.
  • The U-curve is incomplete: push complexity past the interpolation threshold and test error descends a second time, sometimes below the old sweet spot.
  • The mechanism: an interpolating model can only vary between training points, and implicit regularization (SGD, dropout, weight decay) nudges it toward smooth in-between behavior -- low variance despite absurd capacity.
  • This is why "just make it bigger" is not as crazy as your statistics textbook implied -- and part of why massively over-parameterized LLMs work at all.

My Take

What I like about double descent is how it rescues classical theory rather than demolishing it. The bias-variance decomposition is still exactly correct -- it's an identity, after all. What changed is our assumption about how variance behaves at extreme complexity: it doesn't blow up forever, it comes back down once the model interpolates everything. The classical figure wasn't wrong, it was cropped. It is quite humbling to me that the field trained on the U-curve for decades, and the interesting part was just off the right edge of the plot. It also makes me a bit more careful about the phrase "overfitting" -- a model with zero training error and a train/validation gap can still be the best model you have.
