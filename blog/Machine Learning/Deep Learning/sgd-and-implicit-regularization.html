SGD and Implicit Regularization

Machine Learning

A concise handwritten version of this note is available as a PDF.

Here is something that bothered me for a while: we train huge neural networks with SGD, no explicit regularizer in sight, and they still generalize well. Where does the regularization come from? It is quite surprising to me when I first learned the answer -- gradient descent itself is not actually optimizing the loss function you wrote down. Because of the discrete step size, it is secretly optimizing a slightly different loss, and that hidden modification acts like a regularizer. This post works out what that hidden loss looks like, first for plain gradient descent, then for SGD -- where the mini-batch noise turns out to be a feature, not a bug.

Discrete Steps Can't Follow the Loss Landscape Perfectly

Suppose we have a model parametrized by φ and a loss function L(φ). Discrete gradient descent updates the parameters as:

φ₁ = φ₀ - η∇L(φ₀)

Now imagine the step size could be infinitesimal. Then the parameters would slide down the loss landscape perfectly, following the curve at every point. We cannot physically do this, but we can write it down -- it's called continuous gradient descent (i.e. gradient flow). Instead of discrete steps, the parameters flow continuously over time t:

dφ/dt = -∇L(φ(t))

So the gradient descent method only minimizes L(φ) "directly" in the limit η → 0. With a finite step size, each update jumps across the landscape rather than following it -- picture the contour plot of the loss: the continuous path curves smoothly toward the minimum, while the discrete path zig-zags across the contours. Same destination in easy cases, but clearly not the same trajectory. Which raises the question: if discrete gradient descent isn't following L(φ), what is it following?

The Loss Gradient Descent Is Actually Optimizing

Here's the trick (this style of argument is called backward error analysis): instead of saying "gradient descent approximately optimizes L(φ)", we flip it around and say gradient descent exactly follows the gradient flow of a slightly different loss L̃(φ). The goal is to find this modified loss -- the loss where discrete and continuous gradient descent work exactly the same, i.e.

-η∇L̃(φ₀) = ∫₀^η dφ/dt · dt    (with φ(0) = φ₀)

Let us assume the gradient of this modified flow is the original gradient plus a correction term of order η:

dφ(t)/dt = -∇L(φ) + η·g(φ)    evaluated at φ = φ(t)

where g is the unknown correction we need to solve for. Now Taylor-expand φ(t + η) around φ(t), taking t to be the point where φ(t) = φ₀:

φ(t+η) = φ(t) + η·dφ/dt + (η²/2)·d²φ/dt² + O(η³)

Dropping the O(η³) remainder and substituting the flow equation (the second derivative comes from differentiating the flow once more through the chain rule):

φ(t+η) ≈ φ₀ + η(-∇L(φ₀) + η·g(φ₀)) + (η²/2)(-∇²L(φ₀)·dφ/dt + ...)
       ≈ φ₀ - η∇L(φ₀) + η²( g(φ₀) + ½·∇²L(φ₀)·∇L(φ₀) )

Note that φ₀ - η∇L(φ₀) is exactly the update discrete gradient descent makes. So for the continuous flow to land in the same place as the discrete step, the η² term must vanish:

g(φ₀) + ½·∇²L(φ₀)·∇L(φ₀) = 0    =>    g(φ₀) = -½·∇²L(φ₀)·∇L(φ₀)

where ∇²L is the Hessian matrix. Plug this back into the flow, and a bit of matrix calculus (∇²L·∇L is exactly ½ the gradient of ||∇L||²) gives the modified loss:

L̃(φ) ≈ L(φ) + (η/4)·||∇L(φ)||²

Here we are. Gradient descent with step size η behaves as if it were doing perfect gradient flow on the original loss plus a penalty on the squared gradient norm, scaled by the learning rate.

What Does This Penalty Actually Do?

The implication: discrete gradient descent prefers places where the gradient norm is smaller. A minimum sitting in a wide, gentle basin has small gradients all around it; a minimum at the bottom of a narrow ravine is surrounded by steep walls, i.e. large gradients. The ||∇L||² penalty makes the flat basin look more attractive -- which connects directly to the folklore that flat minima generalize better than sharp ones.

One caveat worth being honest about. At any exact minimum, ∇L = 0, so the penalty is zero there -- the value of every minimum is unchanged, and the minimum positions of the continuous and discrete dynamics coincide. What changes is the path: the penalty reshapes the landscape along the way, so discrete gradient descent may end up in a different minimum than the idealized flow would. The regularization acts on the journey, not the destination. Also notice the penalty scales with η -- a larger learning rate means stronger implicit regularization, which is one reason cranking the learning rate down to something tiny doesn't always help generalization (something I found genuinely counterintuitive the first time).

Now Add Mini-Batches: Implicit Regularization in SGD

SGD doesn't compute the full gradient -- it uses one mini-batch at a time, cycling through B batches per epoch, each contributing its own gradient ∇L_b. Rhetorical question: does the noise from mini-batching just make the analysis above messier, or does it do something interesting? Running the same backward error analysis over one epoch of SGD gives:

L̃_SGD(φ) = L(φ) + (η/4)·||∇L||² + (η/4B)·Σ_{b=1}^{B} ||∇L_b - ∇L||²

where B is the total number of batches. The first two terms are exactly what gradient descent had. But SGD picks up an extra regularization term: the average squared deviation of each batch gradient from the total gradient -- essentially the variance of the mini-batch gradients.

So compared with full-batch gradient descent, SGD prefers positions where the gradient is stable, i.e. where the gradient computed on each batch agrees with the total gradient. Think about what that means for generalization: if a minimum only looks good because a few batches (a few subsets of the data) pull hard toward it while the others disagree, SGD is penalized for going there. It favors solutions that every part of the dataset roughly agrees on -- which is more or less the definition of a solution that isn't overfitting to particular examples. The gradient noise everyone treats as the price of cheap updates is quietly doing regularization work for free.

This also gives a cleaner way to think about the batch-size folklore: smaller batches mean noisier gradients, hence a larger variance term, hence stronger implicit regularization -- one reason very large batch training tends to need other tricks (learning rate scaling, explicit regularization) to match the generalization of small-batch training.

Summary

  • Gradient descent with finite η does not optimize L(φ) -- it exactly follows the gradient flow of a modified loss L̃(φ) ≈ L(φ) + (η/4)||∇L||². This is backward error analysis: don't ask how wrong the algorithm is, ask what problem it solves exactly.
  • The ||∇L||² penalty means discrete gradient descent prefers flat regions, and the effect scales with the learning rate -- big steps regularize harder.
  • The minima themselves don't move; the path does, so discrete and continuous dynamics may end up in different minima.
  • SGD adds a further term, (η/4B)·Σ_b ||∇L_b - ∇L||² -- it penalizes disagreement between batch gradients and the full gradient, pushing toward solutions the whole dataset agrees on.
  • Mini-batch noise isn't just tolerable, it's useful: the noise is the regularizer.

My Take

What I like most about this analysis is the reframing. My instinct used to be that discreteness and noise are imperfections -- things standing between us and the "true" optimization we'd do with infinite compute and infinitesimal steps. The backward error analysis view says the opposite: those imperfections define a different, arguably better objective, and the ||∇L||² and gradient-variance penalties fall out of a two-line Taylor expansion. It also demystifies a lot of practitioner folklore for me -- why large learning rates and small batches often generalize better was always stated as an empirical fact, and here is a concrete mechanism sitting behind it. The caveat I keep in mind: this is an O(η²) approximation, so for the large learning rates people actually use, it's a guide to intuition rather than a precise description. Still, "SGD prefers minima where every batch agrees" is the kind of one-sentence takeaway I wish someone had told me years ago.
