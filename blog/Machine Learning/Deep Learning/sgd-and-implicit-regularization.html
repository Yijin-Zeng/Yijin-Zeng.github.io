SGD and Implicit Regularization

Machine Learning

A concise handwritten version of this note is available as a PDF.

Stochastic gradient descent (SGD) is one big reason why deep learning can be trained (relatively) easily and generalize well. SGD and its variant (e.g. Adam) is used for optimizing almost all deep learning models. It is probably well-known that by introducing randomness, SGD can help find the global minimum by escaping the local minimum. However, less people know that SGD is also a implicit regularizer which could help the model generalize better.

Discrete Steps Can't Follow the Loss Landscape Perfectly

Suppose we have a model parametrized by φ and a loss function L(φ). Discrete gradient descent updates the parameters as:

φ₁ = φ₀ - η∇L(φ₀)

Now imagine the step size could be infinitesimal. Then the parameters would slide down the loss landscape perfectly, following the curve at every point. We cannot physically do this, but we can write it down mathematically below. This is called continuous gradient descent (i.e. gradient flow). Instead of discrete steps, the parameters flow continuously over time t:

dφ/dt = -∇L(φ(t))

So the gradient descent method only minimizes L(φ) "directly" in the limit η → 0. With a finite step size, each update jumps across the landscape rather than following it perfectly. Consider contour plot of the loss: the continuous path curves smoothly toward the minimum, while the discrete path jumps across the contours. In some cases, they will end up the same local or global minimum, but they clearly not have same trajectory. This raises a question: if discrete gradient descent isn't following L(φ), what is it following?

The Loss Gradient Descent Is Actually Optimizing

We consider a trick known as backward error analysis: instead of saying "gradient descent approximately optimizes L(φ)", we flip it around and say gradient descent exactly follows the gradient flow of a slightly different loss L̃(φ). The goal is to find this modified loss.

-η∇L̃(φ₀) = ∫₀^η dφ/dt · dt    (with φ(0) = φ₀)

Let us assume the gradient of this modified flow is the original gradient plus a correction term of order η:

dφ(t)/dt = -∇L(φ) + η·g(φ)    evaluated at φ = φ(t)

where g is the unknown correction we need to solve for. Now Taylor-expand φ(t + η) around φ(t), taking t to be the point where φ(t) = φ₀:

φ(t+η) = φ(t) + η·dφ/dt + (η²/2)·d²φ/dt² + O(η³)

Dropping the O(η³) remainder and substituting the flow equation (the second derivative comes from differentiating the flow once more through the chain rule):

φ(t+η) ≈ φ₀ + η(-∇L(φ₀) + η·g(φ₀)) + (η²/2)(-∇²L(φ₀)·dφ/dt + ...)
       ≈ φ₀ - η∇L(φ₀) + η²( g(φ₀) + 1/2·∇²L(φ₀)·∇L(φ₀) )

Note that φ₀ - η∇L(φ₀) is exactly the update discrete gradient descent makes. So for the continuous flow to land in the same place as the discrete step, the η² term must vanish:

g(φ₀) + 1/2·∇²L(φ₀)·∇L(φ₀) = 0    =>    g(φ₀) = -1/2·∇²L(φ₀)·∇L(φ₀)

where ∇²L is the Hessian matrix. Plug this back into the flow, and a bit of matrix calculus (∇²L·∇L is 1/2 the gradient of ||∇L||²) gives the modified loss:

L̃(φ) ≈ L(φ) + (η/4)·||∇L(φ)||²

Thus, we have shown that Gradient descent with step size η behaves as if it were doing perfect gradient flow on the original loss plus a penalty on the squared gradient norm, scaled by the learning rate.

What Does This Penalty Actually Do?

The implication: discrete gradient descent prefers places where the gradient norm is smaller. A minimum sitting in a wide, gentle basin has small gradients all around it; a minimum at the bottom of a narrow ravine is surrounded by steep walls, i.e. large gradients. The ||∇L||² penalty makes the flat basin look more attractive, which connects directly to the assumption that flat minima generalize better than sharp ones.

Note that at any exact minimum, ∇L = 0, so the penalty is zero. The value of every minimum is unchanged, and the minimum positions of the continuous and discrete dynamics coincide. What changes is the path. The penalty reshapes the landscape along the way, so discrete gradient descent may end up in a different minimum than the idealized flow would. The regularization acts on the journey, not the destination. Also notice the penalty scales with η. A larger learning rate means stronger implicit regularization, which is one reason changing the learning rate down to something tiny doesn't always help generalization.

Implicit Regularization in SGD

SGD doesn't compute the full gradient, it uses one mini-batch at a time, cycling through B batches per epoch, each contributing its own gradient ∇L_b. Running the same backward error analysis over one epoch of SGD gives:

L̃_SGD(φ) = L(φ) + (η/4)·||∇L||² + (η/4B)·Σ_{b=1}^{B} ||∇L_b - ∇L||²

where B is the total number of batches. The first two terms are exactly what gradient descent had. But SGD picks up an extra regularization term: the average squared deviation of each batch gradient from the total gradient, essentially the variance of the mini-batch gradients.

So compared with full-batch gradient descent, SGD prefers positions where the gradient is stable, i.e. where the gradient computed on each batch agrees with the total gradient. Intuitively, if a minimum only looks good because a few batches (a few subsets of the data) points toward it while the others disagree, SGD is penalized for going there. It favors solutions that every part of the dataset roughly agrees on.

This also gives a cleaner way to think about the batch-size assumption: smaller batches mean noisier gradients, hence a larger variance term, hence stronger implicit regularization. One reason very large batch training tends to need other tricks (learning rate scaling, explicit regularization) to match the generalization of small-batch training.
