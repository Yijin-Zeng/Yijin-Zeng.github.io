Residual Connections

Machine Learning

A concise handwritten version of this note is available as a PDF.

With a large amount of data, deeper neural networks often achieve better training loss and generalization. However, before residual connections, training networks with over 100 layers was difficult.

Historically, researchers observed that simply adding more layers caused both training and validation loss to go up. Because the training loss itself got worse, it implies that the issue was a failure in the training process, not overfitting (where only the validation loss would increase).

The Problem: Deeper Networks Fail to Train

This detail matters more than it looks. If only validation loss went up while training loss went down, then it is a generalization problem. But since training loss going up too, this means the problem is not generalization, it's the training itself. The optimizer can't find a good solution, even though we know one exists (the identity extension of the shallower network).

A Possible Explanation: Shattered Gradients

Why would training fail? One possible explanation is known as shattered gradients. In standard training, the gradient with respect to an early layer is a long chain rule product:

∂y/∂f1 = (∂y/∂fn) · (∂fn/∂fn-1) · ... · (∂f2/∂f1)

As the model goes deeper and deeper, a small change in x leads to very different gradients. The loss surface effectively keeps changing with every batch, so the optimizer is chasing a moving target.

To picture it, consider a univariate input x mapped to a univariate output y, and plot the gradient ∂y/∂x as a function of x:

Shallow network (1-2 layers)          Deep network (shattered)

∂y/∂x                                 ∂y/∂x
  │        ___/‾‾                       │  ╱╲    ╱╲ ╱╲
  │    ___/                             │ ╱  ╲╱╲╱  ╳  ╲╱╲
  │ __/                                 │╱    ╲╱   ╱╲   ╲
  └──────────────── x                   └──────────────── x
  smooth, structured                    looks like white noise

For the shallow network the gradient is a smooth, well-behaved function of the input. For the deep network it looks like noise, nearby inputs give wildly different gradients, so the optimizer struggles to find a consistent descent direction.

Residual Connection

The idea of residual connection is simple. Instead of each layer replacing its input, each layer adds to it. For n = 3, this means

h1 = x  + f1(x; φ1)
h2 = h1 + f2(h1; φ2)
y  = h2 + f3(h2; φ3)

As a diagram, the input takes a shortcut around each block:

     ┌────────┐   ┌────────┐   ┌────────┐
     │       ▼   │        ▼   │       ▼
x ──→ f₁ ──→ ⊕ ──→ f₂ ──→ ⊕ ──→ f₃ ──→ ⊕ ──→ y

Unroll the recursion, we have

y = x
  + f1(x; φ1)
  + f2(x + f1(x; φ1); φ2 )
  + f3(x + f1(x; φ1) + f2(x + f1(x; φ1); φ2); φ3)

We have three observations from the formula above:

  • The lower-level information is kept. Lower level layers outputs has direct impact on the outputs.
  • A residual network is essentially an ensemble model. The output is a sum of terms of different depths: a depth-0 term (x itself), a depth-1 term, up to a depth-3 term. We can think of residual connections as an ensemble of neural networks of varying depth, trained jointly.
  • There are many different paths from input to output. Information doesn't have to survive every layer; it just needs one good path from input to output.

Implementation Details

Two things to be careful about when implementing residual networks: the order of operations inside a block, and exploding activations. Both bit people in practice.

Order of Operations

The most natural block is Linear → ReLU, then add:

x ──→ [Linear] ──→ [ReLU] ──→ ⊕ ──→
└───────────────────────────────┘

The problem of this block is that since the branch ends in a ReLU, it can only add positive values to the residual stream. So the values just get bigger and bigger.

Swapping to ReLU → Linear fixes the output side, but now the ReLU sits directly on the input, and if the incoming values are all negative the block is dead. The practical answer is to put linear layers at both ends, e.g. a first Linear before the block (preventing all-negative inputs into ReLU) and end the branch with Linear so it can add values of either sign:

x → [Linear] ──→ [ReLU] → [Linear] → [ReLU] → [Linear] ──→ ⊕ ──→
              └────────────────────────────────────────────────┘

In practice a residual block can contain multiple layers like this. The rule of thumb is just that the thing you add back should be able to take any sign.

Exploding Variance

Suppose x has variance 1, and each fi contributes an independent unit-variance output. Since we keep adding, variances add up:

x ──→ f1 ──→ ⊕ ──→ f2 ──→ ⊕ ──→ f3 ──→ ⊕ ──→ y
var: 1             2            4            8
                variance grows exponentially
                (and the backward pass behaves the same way)

Solution 1: rescale by 1/√2 after each addition. This keeps the variance pinned near 1... but it's not good. Unrolling the sum again, the output becomes

y = (1/√2)³ (x + f1(x))
  + (1/√2)² f2(·)
  + (1/√2)  f3(·)

The variance is stable, but the contributions of the lower layers are scaled down exponentially. That was the whole point of the residual connection, so the shattered gradient problem persists.

Solution 2: batch norm inside the branch, before fᵢ.

x ──→ [BN] → f1 ──→ ⊕ ──→ [BN] → f2 ──→ ⊕ ──→ [BN] → f3 ──→ ⊕ ──→
var:         1                    2                  3

Each branch now contributes a fixed variance-1 amount, so the total variance grows linearly instead of exponentially, and importantly, the skip path is not scaled down.

Side effect of residual connections: at the begining of the training, the shallower layers have bigger impact than deeper layers, so at the beginning of training, the network is effectively shallower. Later layers barely move the output, and depth gets switched on gradually as training progresses.

Why Does Residual Connections Work So Well?

There isn't one definite clean answer, but there are several plausible explanations:

  1. The work for each layer is easier. Without the skip, a layer must learn the full transformation f(x), i.e. it has to consider how to transform its input toward the output. With the skip, it only needs to learn the residual f(x) − x, i.e. each layer just "adds" information to the current solution.
  2. The loss landscape is much smoother. Lower-layer inputs contribute to the output directly through the skip paths, so it's much easier to take their gradients. Even if the gradient is blocked inside some layer (a dead ReLU, say), the layers below can still update through the shortcut.
  3. It's an ensemble of many small models.
  4. With many different paths, there may be one with a good prior. This connects to the lottery ticket hypothesis: among exponentially many subnetworks/paths, some are well-initialized winners, and the residual structure allows them dominate.
