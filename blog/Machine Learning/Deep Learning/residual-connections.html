Residual Connections

Machine Learning

A concise handwritten version of this note is available as a PDF.

Residual connections are one of the main reasons deep neural networks can be trained at all. A standard deep network is just a composition of functions:

y = fₙ( ... f₃( f₂( f₁(x; φ₁); φ₂ ); φ₃ ) ... ; φₙ)

The observation from AlexNet-style architectures: as n grows, i.e. the network gets deeper, both training and validation loss go up. That's a strange result on its own -- a deeper network can always represent a shallower one, by setting the extra layers to the identity, so depth should never hurt training loss even in the worst case.

The Problem: Deeper Networks Fail to Train

This detail matters more than it looks. If only validation loss went up while training loss went down, we'd call it overfitting -- a generalization problem. But training loss going up too means the problem is not generalization, it's the training itself. The optimizer can't find a good solution, even though we know one exists (the identity extension of the shallower network).

A Possible Explanation: Shattered Gradients

Why would training fail? One compelling explanation is shattered gradients. In standard training, the gradient with respect to an early layer is a long chain rule product:

∂y/∂f₁ = (∂y/∂fₙ) · (∂fₙ/∂fₙ₋₁) · ... · (∂f₂/∂f₁)

As the model goes deeper and deeper, a small change in x leads to very different gradients. The loss surface effectively keeps changing with every batch -- the optimizer is chasing a moving target.

To picture it, consider a univariate input x mapped to a univariate output y, and plot the gradient ∂y/∂x as a function of x:

Shallow network (1-2 layers)          Deep network (shattered)

∂y/∂x                                 ∂y/∂x
  │        ___/‾‾                       │  ╱╲    ╱╲ ╱╲
  │    ___/                             │ ╱  ╲╱╲╱  ╳  ╲╱╲
  │ __/                                 │╱    ╲╱   ╱╲   ╲
  └──────────────── x                   └──────────────── x
  smooth, structured                    looks like white noise

For the shallow network the gradient is a smooth, well-behaved function of the input. For the deep network it looks like noise -- nearby inputs give wildly different gradients. Good luck doing gradient descent on that.

The Fix: Add the Input Back

The residual connection is almost embarrassingly simple. Instead of each layer replacing its input, each layer adds to it. For n = 3:

h₁ = x  + f₁(x; φ₁)
h₂ = h₁ + f₂(h₁; φ₂)
y  = h₂ + f₃(h₂; φ₃)

As a diagram, the input takes a shortcut around each block:

     ┌───────┐   ┌───────┐   ┌───────┐
     │       ▼   │       ▼   │       ▼
x ──→ f₁ ──→ ⊕ ──→ f₂ ──→ ⊕ ──→ f₃ ──→ ⊕ ──→ y

So what does this actually buy us? Unroll the recursion:

y = x
  + f₁(x; φ₁)
  + f₂( x + f₁(x; φ₁); φ₂ )
  + f₃( x + f₁(x; φ₁) + f₂(x + f₁(x; φ₁); φ₂); φ₃ )

Three things fall out of this formula:

  • The lower-level information is kept. The raw x is literally a summand of the output -- it can never be destroyed by a bad layer in the middle.
  • A residual network is an ensemble. The output is a sum of terms of different "depths": a depth-0 term (x itself), a depth-1 term, up to a depth-3 term. We can think of residual connections as an ensemble of neural networks of varying depth, trained jointly.
  • There are many different paths from input to output. Information doesn't have to survive every layer; it just needs one good path.

Implementation Details That Actually Matter

Two things to be careful about when implementing residual networks: the order of operations inside a block, and exploding activations. Both bit people in practice.

Order of Operations

The most natural block is Linear → ReLU, then add:

x ──→ [Linear] ──→ [ReLU] ──→ ⊕ ──→
└─────────────────────────────┘

Problem: the branch ends in a ReLU, so it can only add positive values to the residual stream. The block can push activations up but never pull them down -- half the correction space is gone.

Swapping to ReLU → Linear fixes the output side, but now the ReLU sits directly on the input, and if the incoming values are all negative the block is dead. The practical answer is to put linear layers at both ends, e.g. a first Linear before the block (preventing all-negative inputs into ReLU) and end the branch with Linear so it can add values of either sign:

x ──→ [ReLU] → [Linear] → [ReLU] → [Linear] ──→ ⊕ ──→
└───────────────────────────────────────────────┘

In practice a residual block can contain multiple layers like this -- the rule of thumb is just that the thing you add back should be able to take any sign.

Exploding Variance

Here's a subtler one. Suppose x has variance 1, and each fᵢ contributes an independent unit-variance output. Since we keep adding, variances add up:

x ──→ f₁ ──→ ⊕ ──→ f₂ ──→ ⊕ ──→ f₃ ──→ ⊕ ──→ y
var: 1        2           4            8
                variance grows exponentially
                (and the backward pass behaves the same way)

Solution 1: rescale by 1/√2 after each addition. This keeps the variance pinned near 1... but it's not good. Unrolling the sum again, the output becomes

y = (1/√2)³ (x + f₁(x))
  + (1/√2)² f₂(·)
  + (1/√2)  f₃(·)

The variance is stable, but the contributions of the lower layers are scaled down exponentially -- the identity path from x gets crushed. That was the whole point of the residual connection, so the shattered gradient problem persists.

Solution 2: batch norm inside the branch, before fᵢ.

x ──→ [BN] → f₁ ──→ ⊕ ──→ [BN] → f₂ ──→ ⊕ ──→ [BN] → f₃ ──→ ⊕ ──→
var: 1               2                  3                   4

Each branch now contributes a fixed variance-1 amount, so the total variance grows linearly instead of exponentially -- and crucially, the skip path is never scaled down.

There's a side effect worth noting: at variance k on the stream, each new layer's variance-1 contribution is relatively small next to it. So at the beginning of training, the network is effectively shallower -- later layers barely move the output, and depth gets "switched on" gradually as training progresses.

So Why Does It Work?

There isn't one clean answer -- there are several explanations, and honestly they're all probably partially right:

  1. The work for each layer is easier. Without the skip, a layer must learn the full transformation f(x) -- it has to consider how to transform its input all the way toward the output. With the skip, it only needs to learn the residual f(x) − x, i.e. each layer just "adds" information to the current solution rather than rebuilding it. Refining is easier than reconstructing.
  2. Shattered gradients are much less prominent, and the loss landscape is much smoother. Lower-layer inputs contribute to the output directly through the skip paths, so it's much easier to take their gradients. Even if the gradient is blocked inside some layer (a dead ReLU, say), the layers below can still update through the shortcut.
  3. It's an ensemble of many small models -- the unrolled-sum view from earlier, made literal.
  4. With many different paths, there may be one with a good prior -- this connects to the lottery ticket hypothesis: among exponentially many subnetworks/paths, some are well-initialized winners, and the residual structure lets them carry the load.

Summary

  • Deeper AlexNet-style networks got worse on training loss too, not just validation loss -- the problem is the training itself, not generalization.
  • One explanation is shattered gradients: as depth grows, the chain-rule product ∂y/∂f₁ becomes wildly sensitive to small changes in x, so the loss surface looks like noise instead of a smooth function.
  • A residual connection replaces "each layer replaces its input" with "each layer adds to it." Unrolling the recursion shows the output is a sum of terms at every depth -- the raw input, plus depth-1 terms, plus depth-2 terms, and so on.
  • That sum view gives three things directly: lower-level information is never destroyed, the network behaves like an ensemble of networks of different depths, and there are many paths from input to output.
  • Implementation matters: a block that ends in ReLU can only add positive values, so linear layers belong at both ends of the block. Left unchecked, variance also grows exponentially through the additions; rescaling by 1/√2 stabilizes variance but crushes the identity path, so batch norm inside each branch is the better fix.
  • Several explanations for why it works are probably all partially true: each layer only has to learn a residual instead of a full transformation, gradients flow more directly to lower layers, the network acts as an ensemble, and among many paths some may already have a good prior.
