Change Point Detection Methods

Statistics

A detailed technical review with derivations is available as a PDF.

Change point detection is about spotting when something fundamental shifts in your data. Think of it like watching a heart rate monitor — most of the time it's steady, but when something happens (exercise, stress, rest), the pattern changes. These transition moments are what we're hunting for.

Why Does This Matter?

Change points show up everywhere:

  • Finance: when market volatility suddenly jumps
  • Manufacturing: when a machine starts drifting out of spec
  • Climate: when temperature trends break from historical patterns
  • Networks: when traffic patterns shift due to an attack or outage

The challenge is distinguishing real structural changes from random noise. That's where these methods come in.

Single Change Point Methods

These techniques assume there's at most one change point in your sequence. They're asking: "did something change, and if so, where?"

1. Cumulative Sum (CUSUM)

CUSUM is elegant in its simplicity. Imagine you're tracking daily temperature and you suspect the mean shifted at some point. CUSUM accumulates evidence of this shift.

The intuition: If there's no change, positive and negative deviations from the mean should cancel out over time. But if the mean shifts upward at time τ, you'll start accumulating positive evidence that grows unbounded.

CUSUM compares two hypotheses at each candidate split point:

  • Before the split: data comes from distribution F₁
  • After the split: data comes from distribution F₂

It computes a statistic that measures how much the split "explains" versus the null hypothesis of no change. When this statistic exceeds a threshold, you declare a change point.

When it works best: When you know the distributions (e.g., normal with different means) and the change is persistent, not just a temporary spike.

2. Likelihood Ratio Test

This is the statistically principled approach. You're asking: "what location for a change point maximizes the likelihood of observing this data?"

The intuition: If there's truly a change at time τ, then modeling the data with a split at τ should fit much better than assuming no change at all. The likelihood ratio quantifies this improvement.

You scan through all possible split points, compute the likelihood for each, and pick the one that maximizes it. Then you test whether this maximum is statistically significant.

The catch: You need to know (or estimate) the parameters of your distributions. Also, choosing the significance threshold is tricky — traditional methods are too conservative for large datasets.

3. t-Test Based Detection

This is CUSUM's practical cousin for when you don't know the distribution parameters.

The intuition: At each candidate split point, compute the sample means before and after. If they're significantly different (via a t-test), that's evidence of a change.

You scan all possible splits and find the one with the largest t-statistic. If it exceeds a threshold, declare that point as your change point.

Why it's useful: No need to know the true means or variances ahead of time. The data tells you.

The trade-off: Setting the threshold is hard. Too low = false alarms. Too high = missed changes.

4. Rank-Based Detection

What if your data isn't even normally distributed? Rank-based methods don't care about the actual values — only their relative ordering.

The intuition: If there's a change point, observations before and after should come from different distributions. This means if you compare any "before" observation with any "after" observation, one should tend to be systematically larger.

The method counts these pairwise comparisons using a sign function, builds a test statistic, and checks if it's extreme enough to declare a change.

When it shines: Robustness. Outliers won't throw it off, and it works regardless of the underlying distribution shape. Perfect for messy real-world data.

Multiple Change Points

Real data rarely has just one change. Maybe a system gradually degrades through multiple stages, or a market goes through several regime shifts. These methods handle that complexity.

1. Binary Segmentation

This is the greedy, recursive approach.

How it works:

  1. Apply a single change point method to the entire sequence
  2. If a change is detected, split the sequence there
  3. Recursively apply the same process to each segment
  4. Stop when no more significant changes are found

The appeal: Simple, fast, intuitive.

The limitation: It's greedy. If the first split isn't optimal, all subsequent splits inherit that mistake. Works great when there's one dominant change, less so when there are multiple subtle shifts.

2. Wild Binary Segmentation (WBS)

This fixes binary segmentation's greedy problem with a clever twist: randomization.

The insight: Instead of always testing the full sequence, randomly sample many subintervals and test each one for a change point. Then aggregate these local findings to identify global change points.

By testing many random windows, WBS avoids getting locked into a bad first decision. It's like getting multiple opinions before committing.

When it wins: When you have multiple change points and they might be clustered together. The randomization helps it find all of them.

3. Pruned Exact Linear Time (PELT)

This is the efficiency champion. PELT solves an optimization problem: find the set of change points that minimizes a cost function (like total variance) plus a penalty for each change point added.

The framework: You're balancing two competing goals:

  • Fit the data well (which suggests more change points)
  • Keep the model simple (which suggests fewer change points)

PELT uses dynamic programming to solve this exactly, but with a pruning trick that makes it run in linear time on average.

The pruning insight: If adding a change point at time t doesn't improve the cost, then it will never be part of the optimal solution for any future time either. So you can discard it permanently.

Why it's powerful: Optimal solution (not greedy), and fast enough for large datasets.

4. Nonparametric Maximum Likelihood

This approach asks: "what's the most likely configuration of change points, without assuming any particular distribution?"

The idea: Use empirical cumulative distribution functions (which make no parametric assumptions) and maximize an integrated likelihood over all possible change point configurations.

It estimates not just where the change points are, but also how many there are, using information criteria like BIC.

The strength: No distributional assumptions. Works for any data.

The cost: Computationally intensive. The optimization problem is hard, requiring dynamic programming tricks to be feasible.

5. Energy-Based Detection

What if your data is multivariate — not just a single time series, but multiple variables tracked simultaneously?

The energy statistic measures the distance between two multivariate distributions by comparing:

  • The average distance between points in the two groups
  • The average distance within each group

If the between-group distance is much larger than the within-group distance, the two segments likely come from different distributions.

You scan through candidate change points, compute the energy statistic for each split, and test for significance using permutation tests.

Why it's useful: Handles multivariate data naturally. Nonparametric. Detects changes in any aspect of the distribution (mean, variance, correlation structure, etc.).

Choosing a Method

Here's a quick decision guide:

  • Know your distribution + expect one change? → CUSUM or Likelihood Ratio Test
  • Unknown distribution + one change? → t-test or rank-based method
  • Multiple changes + want speed? → Binary Segmentation or WBS
  • Multiple changes + want optimality? → PELT
  • Multivariate data? → Energy-based detection
  • No assumptions at all? → Nonparametric maximum likelihood or rank-based methods

The Real Challenge: Thresholds

Almost every method requires choosing a threshold for declaring a change. Set it too low, and you'll see changes everywhere (false positives). Set it too high, and you'll miss real changes (false negatives).

Common approaches:

  • Control false alarm rate: Use probabilistic bounds (like Bonferroni correction) to keep false positives rare
  • Monte Carlo simulation: Generate data under the null hypothesis (no change) and see what threshold gives you the false alarm rate you want
  • Cross-validation: If you have labeled data, tune the threshold to maximize detection accuracy

There's no free lunch — you're always trading off between sensitivity and false alarms.

Final Thoughts

Change point detection is fundamentally about finding structure in sequences. Each method makes different trade-offs between assumptions, computational cost, and statistical power.

The best approach depends on your data and your priorities. But understanding the intuition behind each method helps you choose wisely — and interpret the results correctly.
