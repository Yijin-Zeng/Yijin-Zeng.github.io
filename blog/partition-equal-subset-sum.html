416. Partition Equal Subset Sum

Leetcode

A concise handwritten version of this note is available as a PDF.

This is a classic dynamic programming problem that beautifully illustrates the transition from brute force (exponential) to memoization to bottom-up DP. The key insight is recognizing that the exponential recursion has only a polynomial number of distinct states.

Problem Statement

Given an array of positive integers, can we find a subset of the array such that the sum of the subset equals a target x?

For example, given [1, 5, 11, 5] with target = 11, the answer is yes: the subset {1, 5, 5} sums to 11.

This is the core subproblem behind LeetCode 416 "Partition Equal Subset Sum." If the total sum of the array is even, we just need to find a subset that sums to sum(nums) / 2.

Solution 1: Brute Force (Recursion)

The most straightforward approach: for each element, we either include it in the subset or exclude it, and recurse on the remaining elements.

def recursive(index, target):
    if target == 0:
        return True
    if target < 0 or index >= len(nums):
        return False

    # Include nums[index] OR exclude nums[index]
    return recursive(index + 1, target - nums[index]) or recursive(index + 1, target)

return recursive(0, x)

Time Complexity

O(2^n), where n = len(nums). We consider all subsets of the array until we find the True case.

Key Observation: Overlapping Subproblems

However, notice that the state space is bounded. Since:

  • 0 <= target <= sum(nums) = m
  • 0 <= index <= n - 1

There are at most n x m different states! The brute force recursion recomputes the same sub-function multiple times. This is analogous to computing Fibonacci numbers naively -- fib(n) calls fib(n-1) and fib(n-2), which share many overlapping subproblems.

Solution 1.5: Recursion with Memoization

The fix is simple: add a cache (e.g., Python's @cache decorator) before the recursive function. This reduces the time complexity to O(m * n), since each distinct state requires O(1) work.

from functools import cache

@cache
def recursive(index, target):
    if target == 0:
        return True
    if target < 0 or index >= len(nums):
        return False
    return recursive(index + 1, target - nums[index]) or recursive(index + 1, target)

return recursive(0, x)

Why Does Memoization Work?

Consider the recursion tree. Each node represents a function call with state (index, target). With memoization:

  • If a state is already in memory, we do not recurse further -- just return the cached result.
  • Each time we "go down" (recurse deeper), we encounter a new state not yet in memory and add it.
  • How many times can we go down? At most m * n times (one per unique state).
  • How many times can we go up (return from calls)? Bounded by 2x the number of times we go down.

Example: Recursion Tree with Memoization

Consider nums = [6, 7, 4, 3] with target sum = 10:

                        isSum(10, [6,7,4,3])
                       /                        \
              include 3                      exclude 3
                     /                            \
          isSum(7, [6,7,4])                isSum(10, [6,7,4])
            /           \                    /            \
    isSum(3,[6,7])  isSum(7,[6,7])   isSum(6,[6,7])  isSum(10,[6,7])
      /       \       /       \        /      \        /       \
 isSum   isSum   isSum   isSum    isSum  isSum   isSum   isSum
 (-4,[6]) (3,[6]) (0,[6]) (7,[6]) (-1,[6]) (6,[6]) (3,[6]) (10,[6])
   |        |       |       |       |        |       |        |
 FALSE    ...    TRUE!    ...    FALSE     ...    CACHED    ...

Notice how isSum(3, [6]) appears multiple times in the tree. Without memoization, we recompute it each time. With memoization, the second occurrence just returns the cached result.

The red numbers in the handwritten notes indicate the order in which states are first added to memory (1, 2, 3, ...). Each addition takes only constant time, and the total number of additions is bounded by m * n.

Solution 2: Dynamic Programming (Bottom-Up)

Instead of top-down recursion with memoization, we can build the solution bottom-up. The idea: maintain a set of all achievable subset sums, then process elements one by one.

Approach

  • Start with the set of achievable sums: {0} (empty subset).
  • For each number in the array, update the set of achievable sums by adding the current number to every existing sum.
  • If the target ever appears in the set, return True.
def canPartition(nums):
    target = sum(nums)
    if target % 2 != 0:
        return False
    target //= 2

    achievable = set()
    achievable.add(0)

    for num in nums:
        next_achievable = set()
        for s in achievable:
            if s + num == target:
                return True
            next_achievable.add(s + num)
        achievable = achievable | next_achievable

    return target in achievable

Alternatively, the classic DP formulation uses a boolean array dp[j] where dp[j] = True means a subset sum of j is achievable:

def canPartition(nums):
    total = sum(nums)
    if total % 2 != 0:
        return False
    target = total // 2

    dp = [False] * (target + 1)
    dp[0] = True

    for num in nums:
        # Traverse backwards to avoid using the same element twice
        for j in range(target, num - 1, -1):
            dp[j] = dp[j] or dp[j - num]

    return dp[target]

Time and Space Complexity

  • Time: O(n * m), where n = len(nums) and m = sum(nums) / 2
  • Space: O(m) using the 1D DP array

Summary

  • Brute force recursion: O(2^n) -- explores all subsets.
  • Recursion + memoization: O(n * m) -- caches overlapping subproblems.
  • Bottom-up DP: O(n * m) -- iteratively builds up achievable sums.
