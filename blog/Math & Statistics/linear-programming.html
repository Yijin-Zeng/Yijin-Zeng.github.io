A Bakery Problem

Imagine you run a bakery selling two kinds of cakes. Cake A sells for a profit of 20 and cake B for 50. Each cake takes one hour to prepare, and you only have 10 hours of prep time. Oven time is different: cake A takes 2 hours and cake B takes 3, with 30 oven hours in total. How many of each should you bake?

max  20x + 50y          (x = number of cake A, y = number of cake B)
x,y
s.t. x + y <= 10        (prep time: one hour each, total <= 10)
     2x + 6y <= 30      (oven time, total <= 30)
     x >= 0, y >= 0

This is a linear programming (LP) problem: a linear target function with linear constraints. It shows up everywhere — scheduling, budget allocation, network routing. The reason it deserves its own theory (rather than just being a special case of constrained optimization) is that the linear structure allows something remarkable: we only ever need to check a handful of "corner" points, instead of searching the whole space.

The Standard Form

The standard form for linear programming is:

max  c^T x
 x
s.t. Ax = b
     x >= 0

Note the constraint is an equality, Ax = b. What if we have inequalities like in the bakery problem? We add a slack variable per constraint: Ax <= b is equivalent to Ax + s = b, s >= 0, where s absorbs the "unused" part of each constraint (i.e. the leftover prep hours). Conversely, an equality Ax = b can be written as two inequalities Ax <= b and -Ax <= b, so the equality form and the inequality form max c^T x s.t. Ax <= b, x >= 0 are fully equivalent. We work with whichever is convenient.

Why Corner Points Are Enough

Back to the bakery. If you draw the constraints on the plane, the feasible region is a polygon, and its corners have very concrete meanings:

  • A (origin): do nothing
  • B: constrained by oven time only
  • C: constrained by prep time only
  • D: constrained by both

To find the maximum, we only need to check these corner points. First, why is that true? Here is the argument from my note. A corner point of a convex set S is (by definition) a point that cannot be written as a strict mixture of two distinct points in S: if x = λy + (1-λ)z with y, z ∈ S and 0 < λ < 1, then y = z. The key claim is:

Because the feasible region S is convex, any point x inside S can be expressed as a weighted sum of its corner points v_1, ..., v_k. That is, x = λ_1 v_1 + ... + λ_k v_k where the weights are non-negative and λ_1 + ... + λ_k = 1. Then for the linear target function f:

f(x) = f(λ_1 v_1 + ... + λ_k v_k)
     = λ_1 f(v_1) + ... + λ_k f(v_k)          (linearity)
     <= (λ_1 + ... + λ_k) max{f(v_1), ..., f(v_k)}
     = max{f(v_1), ..., f(v_k)}

So no interior point can ever beat the best corner. Of course, the key claim itself needs to be proved. To see why it holds, take any point x inside a quadrilateral ABDC: draw a line through x, it exits through two edges at points x_1 and x_2, so x = λ_1 x_1 + λ_2 x_2 with λ_1 + λ_2 = 1. But x_1 sits on an edge, so x_1 = λ_3 A + λ_4 B, and similarly x_2 = λ_5 C + λ_6 D. Substituting back, x becomes a weighted sum of the four corners, and (after a small computation) the weights still sum to 1. The formal proof uses the same idea by induction on dimension.

One caveat worth remembering: in the bakery example, the optimal corner D is not an integer point — you cannot bake 7.5 cakes. LP happily gives fractional answers, so for integer problems you need to check around the LP optimum (this is the entry door to integer programming, a much harder problem).

Counting the Corner Points

So corner points are enough. How many are there? Suppose we have n variables with m equality constraints (as in standard form) plus the non-negative constraints.

If m = 1, we get n candidate corner points of the form "one variable is nonzero, all others are zero" (plus the point where all variables are zero, so n+1 in total). If m > 1, the pattern generalizes: we select m variables from all n variables to satisfy the m equation constraints, while all other n-m variables are set to 0. This gives at most C(n, m) corner points. It is only an upper bound, because not all selected combinations produce valid corner points, as we will see.

Denote A = (a_1, a_2, ..., a_n) by its columns. To satisfy Ax = b at all, we need b ∈ col(a_1, ..., a_n); if not, the LP problem simply has no solution. If b is in the column space, we get either one solution or infinitely many. The one-solution and no-solution cases are straightforward, so focus on the infinite case. Partition the columns:

Ax = B x_B + N x_N = b

where B = the m selected columns (a_i1, ..., a_im)
      N = the remaining n-m columns, with x_N set to 0
  • If B is invertible: x_B = B^{-1} b, x_N = 0 is a valid corner point.
  • If B is not invertible: the system B x_B = b has either no solution, infinitely many solutions (in both cases, no corner point for this selection), or exactly one solution — which again gives a valid corner point.

Two notes here. First, x_N has to be exactly 0, otherwise the point is not a corner point. Second, the C(n, m) combinations do include all possible corner points: if we selected more than m variables, the corresponding columns cannot be independent (so not corner points); if we selected fewer than m, that case is already covered by the non-invertible-B analysis above.

The Simplex Algorithm

We know an optimum (if it exists) sits at a corner point. However, there are too many corner points — up to C(n, m) — to check one by one. The simplex algorithm walks along the edges of the polygon instead: start at a corner, move to a neighboring corner whenever it increases the target, and stop when no neighbor improves. It is quite satisfying to me that because the feasible region is convex and the target is linear, a local maximum here is automatically the global maximum — greedy hill-climbing on corners is actually optimal.

  1. Introduce slack variables if there are inequality constraints, to reach standard form.
  2. Find a starting corner point. The m selected variables form the basis; the non-selected n-m variables (the non-basis) are set to 0. This step is harder than it sounds: we need to solve Ax = b and find a solution where all x >= 0. Finding some solution is easy; there is no guarantee it is non-negative.
  3. Check for optimality. Express the target z in terms of non-basis variables only. If we cannot increase any non-basis variable to make the target larger, this is the maximum point — stop. (A non-basis variable sits at 0, so it can only increase; otherwise it would go negative.)
  4. Pivot. Choose a non-basis variable (normally the one with the biggest coefficient) whose increase raises the target, and increase it from 0 until one of the m basic variables hits 0 first. Then change basis: bring the chosen variable in, drop the basic variable that hit 0.
  5. Repeat steps 3 and 4.

A Worked Example

max  z = 3x_1 + 2x_2
s.t. x_1 + x_2 <= 4
     x_1 + 3x_2 <= 6
     x_1, x_2 >= 0

Step 1 (slack variables). The problem is equivalent to:

max  z = 3x_1 + 2x_2
s.t. x_1 + x_2 + s_1 = 4
     x_1 + 3x_2 + s_2 = 6
     x_1, x_2, s_1, s_2 >= 0

Step 2 (entry point). This example has an easy one: take basis B = {s_1, s_2} and non-basis N = {x_1, x_2}. Setting x_1 = x_2 = 0 immediately gives s_1 = 4, s_2 = 6. So our entry point is (0, 0, 4, 6) with z = 0.

Step 3 (pivot). The target expressed in non-basis variables is z = 3x_1 + 2x_2. The coefficient 3 is positive and larger than 2, so we bring x_1 into the basis while keeping x_2 = 0. From the constraints, s_1 = 4 - x_1 and s_2 = 6 - x_1. As x_1 grows, s_1 hits 0 first (at x_1 = 4), so we drop s_1 from the basis. New basis: x_1 = 4, s_2 = 2; new non-basis: x_2 = s_1 = 0; now z = 12. (Re-expressing z in terms of the new non-basis is always possible, since x_B = B^{-1}(b - N x_N) and hence z = c_B^T x_B + c_N^T x_N is a function of x_N alone.)

Step 4 (check). From x_1 + x_2 + s_1 = 4 we get x_1 = 4 - s_1 - x_2, so:

z = 3x_1 + 2x_2 = 12 - 3s_1 - x_2

Both coefficients on the non-basis variables are negative: increasing either s_1 or x_2 can only decrease z. Stop here. The optimum is x_1 = 4, x_2 = 0 with z = 12.

My Take

What I like most about linear programming is how the geometry does all the heavy lifting. The moment you accept "convex feasible region + linear target implies optimum at a corner", the whole subject reduces to bookkeeping: corners are just choices of m columns with an invertible B, and simplex is just greedy walking between them. It is quite surprising to me when I first realized that the algebraic pivot rule in simplex (swap one variable in the basis) is literally the geometric act of sliding along one edge of the polygon — two views of the same move. The honest caveats: finding a starting corner is genuinely non-trivial, C(n, m) can be astronomical in the worst case (simplex has exponential worst-case examples, though it is fast in practice), and the fractional-cake problem reminds us that real-world "count" variables push us into integer programming, where all this elegance gets much more expensive.
