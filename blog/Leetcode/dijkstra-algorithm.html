Dijkstra's Algorithm

Leetcode

A concise handwritten version of this note is available as a PDF.

Dijkstra's algorithm finds the shortest path in a weighted graph, and it is surprisingly elegant once you see how the priority queue guarantees optimality. See LeetCode 743: Network Delay Time for a classic application.

Problem Statement

Given a weighted graph, find the minimum-cost path from a starting node to an end node. For example, consider the following graph and the task of finding the shortest path from node A to node F:

Dijkstra's algorithm solves this efficiently using a priority queue (min-heap) to always expand the cheapest unvisited node first.

Algorithm Implementation

The key idea is to use a min-heap to maintain candidate paths, always processing the shortest known path first. A dictionary path records the confirmed shortest cost to each visited node.

import heapq

def dijkstra(graph, start, end):
    heap = []
    heapq.heappush(heap, (0, start))  # (cost, node) - start with cost 0
    path = {}  # stores the shortest path cost to each node

    while heap:
        current_cost, current_node = heapq.heappop(heap)

        if current_node in path:
            continue  # already found a shorter path to this node

        path[current_node] = current_cost

        for neighbor, cost in graph[current_node].items():
            next_cost = current_cost + cost
            if neighbor not in path:
                heapq.heappush(heap, (next_cost, neighbor))

    return path[end]

Step-by-Step Trace

Consider a small graph where node 0 connects to node 1 (cost 1) and node 4 (cost 3), and node 1 connects to node 6 (cost 2). The algorithm processes as follows:

  1. Start: push (0, 0) onto the heap
  2. Pop (0, 0) → heap becomes [(1, 1), (3, 4)], path: {0: 0}
  3. Pop (1, 1) → heap becomes [(3, 4), (3, 6)], path: {0: 0, 1: 1}
  4. Pop (3, 4) → path: {0: 0, 1: 1, 4: 3}
  5. Pop (3, 6) → path: {0: 0, 1: 1, 4: 3, 6: 3}

Why the "Skip" Check is Necessary

The if current_node in path: continue check is essential. A node can appear multiple times in the heap (pushed from different paths). Without this check, we would process the same node multiple times with suboptimal costs, leading to incorrect results.

Key Insights

Here is the key insight: since we are using a priority queue (min-heap), each successive current_cost popped from the heap is guaranteed to be greater than or equal to the previous current_cost. This property leads to several important implications:

1. First pop is the shortest path

If a node is popped for the first time, the corresponding current_cost MUST be the minimum cost to reach it. The priority queue always yields the smallest cost first.

2. Subsequent pops can be safely ignored

If heappop returns a node already in path, the cost is equal to or larger than what we already recorded. Skip it.

3. All reachable nodes will be visited

Every reachable node will eventually be popped and added to path with its optimal cost.

Time Complexity

The time complexity is O(E log V), where E is the number of edges and V is the number of vertices.

Why?

  • Each node will be "visited" (processed) exactly once. Although a node may be pushed onto the heap multiple times, all pops after the first are skipped via the continue check.
  • For each visited node, we loop through all its neighbors. Across all nodes, the total number of neighbor iterations equals the number of edges E.
  • Each neighbor iteration may trigger a heappush operation, which costs O(log V) since the heap can hold at most V entries (in practice up to E, but log E = O(log V) for connected graphs).
  • Therefore total work: V * (average neighbors) * log V = E * log V = O(E log V).

Reference Problem

LeetCode 743 "Network Delay Time" asks: given a directed weighted graph, find the time it takes for a signal to reach all nodes from a source. This is a direct application of Dijkstra's algorithm -- compute shortest paths from the source to all nodes, then return the maximum value in path.
