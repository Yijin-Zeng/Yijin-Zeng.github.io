Direct Preference Optimization (DPO)

LLM

A concise handwritten version of this note is available as a PDF.

Direct Preference Optimization (DPO) is a post-training method for aligning language models with human preferences, such as making them more helpful, positive, and harmless. Another (perhaps more well-known) post-training method is reinforcement learning from human feedback (RLHF). Unlike RLHF, which is complicated and unstable because it requires to train a seperate value model for addressing the credit assignment problem, DPO frames the entire alignment problem as a simple classification problem.

The Core Idea

In RLHF, we build a separate value model to address the credit assignment problem to figure out which tokens deserve credit for a good response. DPO avoids this issue by considering a simpler problem.

How DPO works?

                          winning response (y_w)
                         /
Prompt (x) --> scored by human preference (could train a score model here as well)
                         \
                          losing response (y_l)

For each prompt, we generate two responses, one is preferred by human (winning) and one is the other (losing). The preferences can come from human directly, or come from a score model trained on human preferences labels. After having the wining and losing responses, we compute the likelihood of each response under two models:

  • Current model: the model we're training (being optimized)
  • Reference model: a frozen copy of the model before DPO training (typically the model after SFT)

The DPO Loss

The loss function of DPO is defined as follows:

-log(σ(β log(πθ(yw|x) / πref(yw|x)) - β log(πθ(yl|x) / πref(yl|x)))),

where:

  • π_θ(y_w|x): probability of generating the winning response under the current model
  • π_ref(y_w|x): probability of generating the winning response under the reference model
  • β: controls how much we want to update the model compared to the reference, If β is large, then σ(β·[...]) → 1, making the loss → 0.
  • σ: sigmoid function

DPO vs RLHF (PPO)

RLHF (PPO) DPO
Number of Models involved 4 (score, value, reference, new model) 2 or 3 (reference, new model, maybe score model)
Training method Reinforcement learning Supervised learning
Gradient level Token level Sequence level
Training style Online (needs to generate) Offline (responses are processes in one batch)
Cost High Low
Performance Better (if trained stably) Lower, but is more stable and easier

Why DPO Is Simpler

RLHF requires:

  • Training a reward model to score outputs
  • Training a value model to estimate expected rewards at each token
  • Running online RL where the model generates outputs, gets scored, and updates itself
  • Dealing with token-level credit assignment by figuring out how each token contributed to the final score

DPO requires:

  • A reference model (frozen) and the current model (being trained)
  • Works on pre-collected preference pairs, no need to generate outputs during training
  • Treats the problem as supervised classification to maximize the likelihood of preferred responses
  • Operates at the sequence level, no need for per-token credit assignment

DPO desgin and why do we say DPO is a classification problem?

In a normal classification problem, we could input the model a lot of wining responses and losing responses and then let the model predict which one is wining which one is losing. However, this is not ideal because

  • Intuitively, language quality is inherently relative, not absolute. A response cannot be objectively classified as a "winner" or "loser" in itself. A losing response to a very simple prompt might still be highly coherent and grammatically correct, while a winning response to a nearly impossible prompt might still contain flaws.
  • More precisely, if we treat this as pointwise classification, the model has to learn an absolute decision boundary for what seperates a "good" versus "bad" response across all possible responses. By treating the problem as a pairwise rank problem instead, the model only has to learn to maximize the gap between the good and bad responses, avoiding the need to calculate absolute quality scores.

Why do we say DPO is a classification problem then?

  • So techanically, DPO is not a classification problem but feels more like a learning to rank problem. However, because intuitively DPO is maximizing the probability of wining responses and minimizing the probability of losing responses, we say it is a classification in an unformal way.

Why do we need the frozen model in DPO?

  • Because we want to improve the current model from the frozen model. If the current model gives high probability to winner response and lower probability to lose response, but the frozen model gives even higher gap, then we have no reason to assume that the current model is doing better here.
