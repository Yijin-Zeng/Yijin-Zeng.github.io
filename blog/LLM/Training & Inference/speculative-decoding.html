Speculative Decoding

LLM

A concise handwritten version of this note is available as a PDF.

Speculative decoding is a clever engineering trick used to make LLMs generate text significantly faster without losing any accuracy or changing the final output distribution.

The Problem: Autoregressive Generation is Slow

Standard autoregressive generation produces tokens one at a time. Each forward pass through the model generates exactly one token, and the next token depends on the previous one. Some would think the computation of the embeddings of the tokens with the billions of the LLM parameters would be the bottleneck, but it is not.

The real constraint during inference is memory bandwidth, not compute. For example, if we want an LLM to generate a 100-word story, doing the math is not the bottleneck, transferring the massive model weights back and forth between memory and the processing units is.

Large models have billions of parameters. For each token generated, the entire model's weights need to be loaded from high-bandwidth memory (HBM) into the compute units. The arithmetic intensity (ratio of compute to memory access) of generating a single token is extremely low, meaning the GPU spends most of its time waiting for data rather than computing. This is the memory-bandwidth bound regime.

The Speculative Decoding Approach

As we discussed above, for LLM, processing a batch of tokens take almost the same time for processing one token, since the majority of the time during inference is moving the weights in and out of the memory. Therefore, if we can process the tokens in a batch during inference, we would be much faster than process one token each time. The speculative decoding approach offers an elegant solution for doing exactly this in three steps:

Step 1: Draft

Let a much smaller, faster model (the "draft model") generate the next $K$ tokens autoregressively. Because the draft model is small, this should be much faster than the big model.

Step 2: Verification

Feed all $K$ drafted tokens into the large model in a single forward pass. The large model processes them all at once using causal self-attention (exactly like during training phase). This is computationally equivalent to what the large model would have done if it had generated those $K$ tokens sequentially, but the key point is that we only move the large model's weights once instead of $K$ times.

So now the large model computes the probability distribution over the next token for every tokens generated by the draft model in a batch.

Step 3: Accept or Reject

During verification, we obtain the large model's probability distribution at each of the $K$ positions. We then decide whether to accept or reject each drafted token using a carefully designed acceptance criterion.

Let $p(w_i)$ denote the probability of word $w_i$ under the large model, and $q(w_i)$ denote the probability under the small (draft) model. We accept each token with probability:

$$\text{acceptance probability} = \min\!\left(1, \frac{p(w_i)}{q(w_i)}\right)$$

Important notes about the accept/reject process:

  1. Sequential rejection: If a token at position $i$ is rejected, all tokens after position $i$ are also rejected.
  2. Rejection resampling: When a token $w_j$ is rejected, we do not waste the computation entirely. Since the large model already computed the next-token distribution at that position during verification, we can sample a replacement token. However, we cannot simply sample from $p$ directly (that would bias the distribution). Instead, we sample from an adjusted distribution: $$\text{sample with probability:} \quad \frac{\max(0,\, p(w_j) - q(w_j))}{\sum_j \max(0,\, p(w_j) - q(w_j))}$$ This sampling from the "residual" distribution ensures correctness (more on this below). Note that this is not ideal in terms of speed, because we wasted the time spent by the draft model on subsequent tokens.
  3. Guaranteed progress: Even if all $K$ drafted tokens are rejected, we still obtain one valid token from the resampling step at the first rejected position (see the last point). So speculative decoding always makes at least as much progress as standard autoregressive decoding per large-model forward pass.

Why Speculative Decoding Does Not Lose Any Accuracy

It is quite surprising to me when I first know that speculative decoding does not lose any accuracy at all, i.e. as if we are using the large model only. It turns out, we can show that, by choosing the acceptance probability and resample probability as we did above, the probability of each token get choosen is exactly the same as sampling from the large model directly. The proof requires only basic probability knowledge:

Setting Up the Probability

The probability that word $w_i$ is output at a given position equals:

$$\begin{aligned} &\Pr(\text{word } i \text{ outputs}) \\ &\quad = \Pr(\text{word } i \text{ is proposed by small model AND accepted}) \\ &\quad + \Pr(\text{proposed word by small model is rejected AND large model samples word } i) \end{aligned}$$

Expanding Each Term

The first term (proposed and accepted):

$$q(w_i) \min\!\left(1, \frac{p(w_i)}{q(w_i)}\right) = \min(q(w_i), p(w_i))$$

For the second term, the probability that the proposed word (whatever it was) gets rejected is： $$\left(1 - \sum_j q(w_j) \min\!\left(1, \frac{p(w_j)}{q(w_j)}\right)\right),$$ i.e. one minus the probability of at least one word is accepted. The probability of sampling $w_i$ from the adjusted distribution is known:

$$\frac{\max(0,\, p(w_i) - q(w_i))}{\sum_j \max(0,\, p(w_j) - q(w_j))}$$ Hence, the second term is $$\left(1 - \sum_j q(w_j) \min\!\left(1, \frac{p(w_j)}{q(w_j)}\right)\right) \cdot \frac{\max(0,\, p(w_i) - q(w_i))}{\sum_j \max(0,\, p(w_j) - q(w_j))}.$$

Simplify The Second Term

Notice that for any valid probability distribution:

$$p(x) = \min(p(x), q(x)) + \max(0,\, p(x) - q(x))$$

Summing over all words:

$$1 = \sum_j p(w_j) = \sum_j \min(p(w_j), q(w_j)) + \sum_j \max(0,\, p(w_j) - q(w_j))$$

This lets us simplify the probability of rejection:

$$\begin{aligned} \Pr(\text{rejection}) &= 1 - \sum_j q(w_j) \min\!\left(1, \frac{p(w_j)}{q(w_j)}\right) \\ &= 1 - \sum_j \min(q(w_j), p(w_j)) \\ &= \sum_j \max(0,\, p(w_j) - q(w_j)) \end{aligned}$$

The Final Result

Substituting back:

$$\begin{aligned} \Pr(\text{word } i \text{ outputs}) &= \min(q(w_i), p(w_i)) + \sum_j \max(0,\, p(w_j) - q(w_j)) \cdot \frac{\max(0,\, p(w_i) - q(w_i))}{\sum_j \max(0,\, p(w_j) - q(w_j))} \\ &= \min(q(w_i), p(w_i)) + \max(0,\, p(w_i) - q(w_i)) \\ &= p(w_i) \end{aligned}$$ In other words, the output probability equals exactly $p(w_i)$, i,e, the probability of drawing the word from the large model directly.

Tree-based Speculative Decoding

Standard speculative decoding already accelerates autoregressive LLM inference a lot, often around $1.5\times \sim 2\times$ faster depending on the draft/target models, the domain, the sampling temperature, etc. However, its efficiency can be improved further.

The Problem: Larger $K$ Hardly Helps

In standard speculative decoding, the draft model proposes a single chain of tokens $t_1 \to t_2 \to \cdots \to t_K$. If $t_i$ is rejected, then $t_{i+1}, \dots, t_K$ are all discarded, no matter how good they were. In practice, this means that on average we only accept about 1–2 tokens each time.

The proposal length $K$ can be seen as a resource that we can spend. Depending on the hardware limits, it could be small (e.g. 8) or large (e.g. 128). Unfortunately, standard speculative decoding hardly benefits from a larger $K$. To see this, assume each draft token is accepted independently with probability $p$. The expected number of accepted tokens for one proposed sequence is

$$\begin{aligned} \mathbb{E} &= \sum_{i=1}^{K-1} i\, p^i (1-p) + K p^K \\ &= \sum_{i=1}^{K-1} i\, p^i - \sum_{i=2}^{K} (i-1)\, p^i + K p^K \\ &= p + \sum_{i=2}^{K-1} p^i - (K-1)p^K + K p^K \\ &= \sum_{i=1}^{K} p^i = \frac{p(1-p^K)}{1-p}. \end{aligned}$$

As $K \to \infty$, this converges to $\frac{p}{1-p}$, and the effect of $K$ decays exponentially. For example, with $p = 0.7$ the expected number of accepted tokens can never exceed $0.7/0.3 \approx 2.3$, no matter how large $K$ is.

Conclusion: for a moderate size $K$ (e.g. 3 or 5), the bottleneck of speculative decoding is the acceptance rate $p$, not $K$.

The Idea: Propose Multiple Candidates at Each Step

Since increasing $K$ has exponentially decaying returns, instead of increasing the number of proposed steps, we increase the probability of acceptance at each step by proposing multiple candidate tokens for each step. This turns the chain into a tree:

Standard SD            Tree-based SD

 accepted tokens        accepted tokens
      |                /       |       \
     t1              t1       t1       t1      ← step 1 (3 candidates, sampled
      |             / \      / \      / \             from q with replacement)
     t2            t2  t2  t2  t2  t2  t2      ← step 2 (each candidate gets its own children)
      |                       ...
     t3                                        ← step 3
      :
     tK

At each step, the draft model samples several candidates (e.g. 3) with replacement from its distribution $q$. Each candidate then serves as the root of its own sub-branch for the next step. If one candidate is rejected, we still have a chance that its siblings are accepted, which directly raises the per-step acceptance rate.

Verifying a Tree in One Batch

As with standard speculative decoding, the target model verifies the whole tree in one forward pass. To verify the tree in one pass, we need to change the classic causal attention mask and use tree attention: as in causal attention, each token only attends to its ancestors in the tree (its parent nodes), and not to its siblings or other branches.

The output is the target model's probability distribution of the next token, conditioned on each node and its parent nodes. These distributions are what we use in the accept/reject step below.

Acceptance, Rejection and Resampling

At each step, suppose the draft model has sampled $m$ candidates $X_1, \dots, X_m \overset{\text{i.i.d.}}{\sim} q$, and the target distribution at this step (given all accepted tokens) is $p$. Define the initial target distribution $p^{(0)} = p$. We go through the candidates in order:

  1. For candidate $j \in \{1, \dots, m\}$ (given that all previous candidates were rejected), accept $t_j$ with probability $$\alpha(t_j) = \min\!\left(1, \frac{p^{(j-1)}(t_j)}{q(t_j)}\right).$$ If accepted, output $x_{\text{out}} = t_j$, and move on to the next step (going down the branch of $t_j$).
  2. Otherwise, update the residual target distribution to $$p^{(j)}(x) = \frac{\max\!\left(0,\, p^{(j-1)}(x) - q(x)\right)}{\sum_{x'} \max\!\left(0,\, p^{(j-1)}(x') - q(x')\right)}$$ and try the next candidate.
  3. If all $m$ candidates are rejected, sample the next token from the final residual distribution, $x_{\text{out}} \sim p^{(m)}$, and stop (the remaining tree is discarded).

Notice that with $m = 1$ this is exactly the standard speculative decoding procedure above.

Why Is It Still Lossless?

We now show that Tree-based speculative decoding we described above is still lossless. To this end, we need to show that each step is lossless, i.e. $\Pr(X_{\text{out}} = x) = p(x)$ for all tokens $x \in \mathcal{V}$ (the vocabulary), where $p$ is the target distribution. We use induction on the number of candidates $m$.

Base case ($m = 1$): only one token is proposed for the branch. This is the standard speculative decoding, which we have already proved.

Inductive step: assume the result holds for $m-1$ i.i.d. candidates from $q$ and any target distribution. Now consider $m$ candidates $X_1, \dots, X_m \overset{\text{i.i.d.}}{\sim} q$ with target $p$. Splitting on whether $X_1$ is accepted,

$$\begin{aligned} \Pr(X_{\text{out}} = x) &= \Pr(\text{accept } X_1 \text{ and } X_1 = x) + \Pr(\text{reject } X_1 \text{ and } X_{\text{out}} = x) \\ &= \min(p(x), q(x)) + \Pr(\text{reject } X_1)\, \Pr(X_{\text{out}} = x \mid \text{reject } X_1). \end{aligned}$$

The rejection probability is the same as in the standard case:

$$\Pr(\text{reject } X_1) = 1 - \sum_{x \in \mathcal{V}} \min(p(x), q(x)) = \sum_{x \in \mathcal{V}} \max(0,\, p(x) - q(x)).$$

For the conditional term, note that after rejecting $X_1$ there are exactly $m-1$ i.i.d. candidates from $q$ left, and the target distribution has become $p^{(1)}$. By the induction hypothesis, $\Pr(X_{\text{out}} = x \mid \text{reject } X_1) = p^{(1)}(x)$, since the hypothesis holds for any target distribution. Plugging in $p^{(1)}(x) = \frac{\max(0,\, p(x) - q(x))}{\sum_{x'} \max(0,\, p(x') - q(x'))}$,

$$\begin{aligned} \Pr(X_{\text{out}} = x) &= \min(p(x), q(x)) + \sum_{x'} \max(0,\, p(x') - q(x')) \cdot \frac{\max(0,\, p(x) - q(x))}{\sum_{x'} \max(0,\, p(x') - q(x'))} \\ &= \min(p(x), q(x)) + \max(0,\, p(x) - q(x)) = p(x). \end{aligned}$$

So each step of tree-based speculative decoding samples exactly from the target distribution, and hence the whole output sequence does too.

It is also easy to show that the per-step acceptance rate is no worse than with a single candidate. The probability that all $m$ candidates are rejected is

$$\prod_{i=1}^{m} \sum_{x \in \mathcal{V}} \max\!\left(0,\, p^{(i-1)}(x) - q(x)\right) \;\le\; \sum_{x \in \mathcal{V}} \max\!\left(0,\, p(x) - q(x)\right),$$

because the $i=1$ factor (using $p^{(0)} = p$) is exactly the single-candidate rejection probability, and every other factor is at most 1. Equivalently, the acceptance rate $1 - \prod_{i=1}^m \sum_x \max(0, p^{(i-1)}(x) - q(x))$ is at least that of standard speculative decoding.

Summary

  • Speculative decoding exploits the memory-bandwidth bound nature of LLM inference by letting a small draft model propose $K$ tokens cheaply, while the large model verify them all in a batch.
  • The accept and resample probabilities are designed such that they mathematically guarantees the output distribution is identical to sampling from the large model alone.
  • In the best case, we get $K+1$ tokens for the cost of one large-model forward pass. In the worst case, we still get 1 token (no worse than standard decoding), although we might waste time on small model generating process.
  • Because the expected number of accepted tokens saturates at $\frac{p}{1-p}$, a larger $K$ has exponentially decaying returns. The bottleneck is the per-step acceptance rate $p$.
  • Tree-based speculative decoding raises the acceptance rate by proposing multiple candidates per step, verifies the whole tree in one pass with tree attention, and uses a sequential accept/residual-resample procedure that remains lossless.
