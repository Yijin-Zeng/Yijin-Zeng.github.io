RLHF: Reinforcement Learning from Human Feedback

LLM

A concise handwritten version of this note is available as a PDF.

Reinforcement learning from human feedack (RLHF) is a techenique that can transfrom a foundation model from a word completing machine into a chatbot or an agent.

Starting Point: Pre-training and SFT

Normally we start with a pre-trained language model by letting the model predicting next tokens. This stage uses a large amount of data and compute, and is where the model learn all the words, grammars, and knowledges to be able to output valid sentences.

After pre-training, the model learns to complete text. In other words, it leans the distribution of the next token given all previous tokens. The word completing is very useful. For example, we can let the pre-trained model to finish a sentence that is half written, or a unfinished stories.

However, in many cases, e.g. if we want to build a chatbot based on the pre-trained model, we want the model being able to follow our instructions, and this is very different from completing a sentence. As an example, if we ask the model a question "how is the weather now?", we want the model to be able to answer this question, e.g. 'it is sunny outside'. Instead, the model might generate another question as a continuation ('is it still raining now?'), because that is sometimes what completing text looks like.

To transform the foundation model into a chatbot or an agent that can answer our questions, or take actions, people often use a techenique known as Supervised Fine-Tuning (SFT), where high-quality data are cherry picked and then model is fine tuned on it. If we are building a chatbot, we normally prepare training samples in a question and answer format, often look like this: {'system': 'You are a useful chatbot...', 'user': 'Can you tell me ...', 'assistant': 'Certainly! ...'} This teaches the model to respond to prompts rather than simply continue text.

So after SFT, the model can answer questions, but it still does not know what a "good" answer looks like from a human perspective. For a given question, there could be many different ways to answer it, and there is in many cases, no objective way to evaluate how good those answers are. However, as humans, we decide which answer we prefer subjectively. That is where RLHF comes in.

Stage 1: Training a Reward Model (Using Human Feedback)

The goal of this stage is to build a scalar reward function that can score any output from the LLM. We denote the reward model as r_θ. It is usually initialized from a fine-tuned LLM (often the same model after SFT).

The Process

We feed a prompt into the fine-tuned model and generate multiple candidate answers. For example, given a prompt, the model produces answers A, B, and C. Human annotators then rank these answers by quality (e.g., A > B > C). The idea here to let annotators to rank, rather than scoring each one, is because humans might not be good at to give exact scores, but are good at pairwise ranking.

                          +--> Answer A --|
                          |               |
Prompt --> Fine-tuned LLM +--> Answer B --|---> Ranked by humans (e.g. A > B > C)
                          |               |
                          +--> Answer C --|

The Loss Function

For each pair of responses where one is preferred over the other (e.g., A is preferred over B), the reward model is trained (fine tuned) using a pairwise loss:

Loss = -log(sigmoid(r_θ(A) - r_θ(B))), where A is preferred over B

More precisely, this is the negative log-sigmoid of the difference in scores, encouraging the reward model to assign a higher score to the preferred response.

After training the reward model, we can evaluate the output of any answer given by the LLM (e.g., score it 4.2). However, what does 4.2 means? is it good or bad? and how should we use this score to refine our model? This is why we need reinforcement learning (RL) at this point.

Stage 2: Proximal Policy Optimization (PPO)

Now we consider how to use the reward model to actually improve the language model's policy via RL. This stage introduces two additional models on top of the policy (the LLM being trained):

  • Score model (reward model r_θ): the frozen reward model from Stage 1 that scores outputs. We take the score from this model as the ground truth.
  • Value model: estimates the expected score of the LLM's output given all current tokens; normally initialized as a copy of the model after SFT (so at the begining, would be very bad at scoring, but will be updated and improved gradually). The value model is a tool for credit assignment, we need to decide how each token contributes to the score.

The Process

                                    +---> Score model ---> a score for the whole output (frozen at this stage)
                                    |
Prompt ---> Model ---> Output ------+
                                    |
                                    +---> Value model ---> estimated score given all tokens so far, so at each token there will be one score
                                    (updated accoring to how close the estimated score for each token and score, e.g. MSE)

The decision logic at each step:

  • If score > estimated_score: the output was better than expected, so increase the probability for the token (taking gradients, and then move the weights along the gradients to decrases the loss for the token)
  • Otherwise: decrease the probability of that token (still taking gradients, but move in opposite direction to increase the loss for the token)

The Advantage

The key signal for the policy update is the advantage:

A = advantage = score - estimated_score

This tells us how much better (or worse) the actual output was compared to what we expected. A positive advantage for a token encouraging the model to output it more often, while a negative advantage discouraging the model. Below, we discuss how the weights of the model is updated.

Vanilla Policy Gradient

We can simply compute the gradient of the log-probability of the output (treating the answer as correct), then update the weights:

weights = weights - delta * gradients

Where delta is proportional to the advantage:

  • If A > 0: increase the probability of this output
  • If A < 0: decrease the probability of this output

The Problem with Vanilla Policy Gradient

In Vanilla Policy Gradient, the gradient can change the weights too much in a single step. This can lead to catastrophic forgetting (a notorious problem in RL and continual learning), i.e. the model may collapse or lose previously learned capabilities.

Proximal Policy Optimization (PPO) - Clipping

PPO solves the instability of massive updates by constraining the probability ratio of the objective function. This ratio for a specific token w is defined as:

r = prob(w under the current, updating policy) / prob(w under the old, frozen policy)

The objective function for PPO is then calculated by multiplying this ratio by the token's Advantage (A):

L_CLIP = - min(r * A, clip(r, 1 - epsilon, 1 + epsilon) * A)

Notice how PPO restricts the ratio between 

[1 - epsilon, 1 + epsilon] (typically, epsilon = 0.2).

For example, if the advantage A is positive (means we want to increase the probability for the token), then without clipping at all, we have L_CLIP = - r * A, in order to minimize this loss, the weights will be moved to maximize r, which means the to increase the probability of the token after updating the weights. Since A is positive, this is what we want, however the risk here without any clipping is that the weights might move too much and causing catastrophic forgetting problem.

With clipping, if r is smaller than 1 - epsilon, then we have L_CLIP = (1 - epsilon) * A, a constant that does not depend on the model weights anymore. So the weights would stop moving because there is no gradients.

Overall, by clipping the ratio within the objective function, the loss curve does not change if the probability of the token tries to change by more than 20% in a single step. This naturally causes the gradients to drop to zero, stopping the weights from moving further. Hence mitigating the catastrophic forgetting problem.
