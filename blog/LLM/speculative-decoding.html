Speculative Decoding

LLM

A concise handwritten version of this note is available as a PDF.

Speculative decoding is a clever engineering trick used to make LLMs generate text significantly faster without losing any accuracy or changing the final output distribution.

The Problem: Autoregressive Generation is Slow

Standard autoregressive generation produces tokens one at a time. Each forward pass through the model generates exactly one token, and the next token depends on the previous one. This sounds like the computation (all those matrix multiplications) would be the bottleneck, but it is not.

The real constraint is memory bandwidth, not compute. For example, if we want an LLM to generate a 100-word story, doing the math is not the bottleneck — transferring the massive model weights back and forth between memory and the processing units is.

Large models have billions of parameters. For each token generated, the entire model's weights need to be loaded from high-bandwidth memory (HBM) into the compute units. The arithmetic intensity (ratio of compute to memory access) of generating a single token is extremely low, meaning the GPU spends most of its time waiting for data rather than computing. This is the memory-bandwidth bound regime.

The Speculative Decoding Approach

The key insight is that if we can process the tokens in a batch, we would be much faster. Notice that dealing tokens in a batch does not reduce compute, but save the time for moving the weights in and out of the memory. The speculative decoding approach offers an elegant solution for doing exactly this in three steps:

Step 1: Draft

Let a much smaller, faster model (the "draft model") generate the next K tokens autoregressively. Because the draft model is small, this should be super fast — it has far fewer weights to move around.

Step 2: Verification

Feed all K drafted tokens into the large model in a single forward pass. The large model processes them all at once using causal self-attention (exactly like during training phase). This is computationally equivalent to what the large model would have done if it had generated those K tokens sequentially, but the key point is that we only move the large model's weights once instead of K times.

So now the large model computes the probability distribution over the next token for every tokens generated by the draft model in a batch.

Step 3: Accept or Reject

During verification, we obtain the large model's probability distribution at each of the K positions. We then decide whether to accept or reject each drafted token using a carefully designed acceptance criterion.

Let p(w_i) denote the probability of word w_i under the large model, and q(w_i) denote the probability under the small (draft) model. We accept each token with probability:

acceptance probability = min(1, p(w_i) / q(w_i))

Important notes about the accept/reject process:

  1. Sequential rejection: If a token at position i is rejected, all tokens after position i are also rejected.
  2. Rejection resampling: When a token w_j is rejected, we do not waste the computation entirely. Since the large model already computed the next-token distribution at that position during verification, we can sample a replacement token. However, we cannot simply sample from p directly (that would bias the distribution). Instead, we sample from an adjusted distribution: 
    sample with probability:  max(0, p(w_j) - q(w_j)) / sum_j max(0, p(w_j) - q(w_j))
    This sampling from the "residual" distribution ensures correctness (more on this below). Note that this is not ideal in terms of speed, because we wasted the time spent by the draft model on subsequent tokens.
  3. Guaranteed progress: Even if all K drafted tokens are rejected, we still obtain one valid token from the resampling step at the first rejected position (see the last point). So speculative decoding always makes at least as much progress as standard autoregressive decoding per large-model forward pass.

Why Speculative Decoding Does Not Lose Any Accuracy

It is quite surprising to me when I first know that speculative decoding does not lose any accuracy at all, i.e. as if we are using the large model only. It turns out, we can show that, by choosing the acceptance probability and resample probability as we did above, the probability of each token get choosen is exactly the same as sampling from the large model directly. The proof requires only basic probability knowledge:

Setting Up the Probability

The probability that word w_i is output at a given position equals:

Pr(word i outputs)
  = Pr(word i is proposed by small model AND accepted)
  + Pr(proposed word by small model is rejected AND large model samples word i)

Expanding Each Term

The first term (proposed and accepted):

q(w_i) * min(1, p(w_i) / q(w_i)) = min(q(w_i), p(w_i))

For the second term, the probability that the proposed word (whatever it was) gets rejected is： 

(1 - sum_j q(w_j) * min(1, p(w_j)/q(w_j))),
i.e. one minus the probability of at least one word is accepted. The probability of sampling w_i from the adjusted distribution is known:

max(0, p(w_i) - q(w_i)) / sum_j max(0, p(w_j) - q(w_j))
Hence, the second term is 
(1 - sum_j q(w_j) * min(1, p(w_j)/q(w_j))) * max(0, p(w_i) - q(w_i)) / sum_j max(0, p(w_j) - q(w_j)).

Simplify The Second Term

Notice that for any valid probability distribution:

p(x) = min(p(x), q(x)) + max(0, p(x) - q(x))

Summing over all words:

1 = sum_j p(w_j) = sum_j min(p(w_j), q(w_j)) + sum_j max(0, p(w_j) - q(w_j))

This lets us simplify the probability of rejection:

Pr(rejection) = 1 - sum_j q(w_j) * min(1, p(w_j)/q(w_j))
             = 1 - sum_j min(q(w_j), p(w_j))
             = sum_j max(0, p(w_j) - q(w_j))

The Final Result

Substituting back:

Pr(word i outputs) = min(q(w_i), p(w_i)) + sum_j max(0, p(w_j) - q(w_j)) * max(0, p(w_i) - q(w_i)) / sum_j max(0, p(w_j) - q(w_j))
                   = min(q(w_i), p(w_i)) + max(0, p(w_i) - q(w_i))
                   = p(w_i)
Here we are, the output probability equals exactly p(w_i), i,e, the probability of drawing the word from the large model directly.

Summary

  • Speculative decoding exploits the memory-bandwidth bound nature of LLM inference by letting a small draft model propose K tokens cheaply, while the large model verify them all in a batch.
  • The accept and resample probabilities are designed such that they mathematically guarantees the output distribution is identical to sampling from the large model alone.
  • In the best case, we get K+1 tokens for the cost of one large-model forward pass. In the worst case, we still get 1 token (no worse than standard decoding), although we might waste time on small model generating process.
