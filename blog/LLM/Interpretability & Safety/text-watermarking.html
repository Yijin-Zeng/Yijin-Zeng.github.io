Text Watermarking

LLM

A concise handwritten version of this note is available as a PDF.

An important question in the age of LLMs is to detect if given texts are generated by LLMs or written by humans. One way to approach this problem is to find how the AI's writings are different than human's, as described in common text detection methods. Another way, and perhaps better way, to approach this is to add invisible watermarking to the texts generated by AI.

Common Text Detection Methods

There are a few common approaches for detecting AI-generated text, each with their own trade-offs.

1. Perplexity-Based Detection

Because LLMs predict the probability for the next word, if for most tokens in the text, an LLM has high confidence about the token given all tokens before it, then it's likely that the text was generated by AI.

Pros:

  • Intuitive and easy to implement

Cons:

  • Most AI companies like OpenAI don't disclose the probabilities (otherwise their models can be distilled easily)
  • Low confidence could come from model A vs model B, not human vs AI
  • Most importantly: if the text is in the training dataset, the model will be very confident. Take Shakespeare's writings for example. A model trained using Romeo and Juliet will be very confident about the texts in the play, but AI doesn't generated them.

2. Statistical Detection

An LLM often writes differently than humans statistically. For example, it could use too many emojis, or all sentence lengths might be long (but humans prefer mixing short and long sentences). One example is that AI uses dashes "—" more often than humans. So if a texts have dashes appeared very often, it is very likely to be generated by AI. Following this logic, we can detect text by examining different statistical properties about the texts.

Pros:

  • Easy to implement and make intuitive sense.

Cons:

  • Not very powerful in general, it could have low detection rate depending on which statistical properties are being tested
  • People who happen to use dashes (or other patterns) are innocent...
  • Can only detect relatively "easy" patterns

3. Classifiers

Train a classifier model to decide if texts are AI-generated by feeding it lots of examples of AI generations and human writings.

Pros:

  • Easy to use and can detect deeper patterns compared to statistical methods described above

Cons:

  • The classifier model is a black box itself, so how do we explain why it's 90%, or 10% sure a text is generated by AI?
  • The model could be biased, e.g., there are study showing OpenAI's text detection model against people who use English as a second language
  • Easy to evade by changing a few words, deliberately adding grammar errors, etc.

Watermarking: A Better Approach

Informally, Watermarking provides identity verification for text by slightly biasing the distribution of each word during inference. The key insight is that we can embed a subtle signal that's impossible for any human to mimic , but easy for anyone knows the signal to detect later.

How It Works

During standard autoregressive generation:

token 1 → token 2 → ... → token k-1 → token k → token k+1 → ...

At each step, the model computes a probability distribution over the entire vocabulary. To watermark, we do the following at each step:

  1. Generate a deterministic hash seed based on token k-1 + OpenAI key (constant, but known by OpenAI only)
  2. Based on the hash seed, a hash function divide all vocabularies into red list or green list with equal probability
  3. If the word is in the green team, the probability of it being drawn will be increased slightly.

Why This Works

Because no one knows the secret hash seed and function, the tokens written by people can only have exactly 50% chance to be in red list or green list.

For a human-written text, we have:

P(i-th word is in green list | written by human)
= sum_{all possible words} P(i-th word = word x and word x is in green list)
= sum_{all possible words} P(word x is in green list)  P(i-th word = word x) (iIdependence)
= 1/2 sum_{all possible words} P(i-th word = word x)
= 1/2

But for text actually generated by the watermarked LLM, this probability is deliberately increased to something like 51%. This slightly increase provides the signal we can detect.

Statistical Detection

To detect watermarked text, we use standard hypothesis testing procedures. Let us denote:

  • S = tokens in green list
  • N = total tokens

Null Hypothesis (H0): The texts are generated by human

Under the null hypothesis, tokens have about 50% chance to be green, so by CLT, the following holds approximately: 

z = (S - tN) / sqrt(Nt(1-t)) ~ N(0, 1)

Alternative Hypothesis (H1): The texts are generated by OpenAI

If the text is watermarked, then we have 

z -> +infty when N -> + infty.

Trade-offs

Pros:

  • Guaranteed detection given long sequence, the power of the test goes to 1 with sample size.
  • Very powerful, and robust, humans can't fake the pattern without knowing the secret key, and can't escape by justing change a few words, adding grammar mistakes etc.

Cons:

  • Company exclusive (requires access to the generation process)
  • Does not work well for short sequences (although maybe no method can work well for short sequences)

Summary

Text watermarking is a powerful abd robust approach for detecting LLM-generated text. By slightly biasing token selection toward a secret "green list" during generation, we create a statistical validated method that's impossible for humans to replicate but easy to detect with hypothesis testing.
