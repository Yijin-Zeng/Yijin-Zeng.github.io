FlashAttention

LLM

A concise handwritten version of this note is available as a PDF.

FlashAttention is one of the many clever ideas that makes LLM more efficient and practical. Standard attention mechanism deal with the full N * N score matrix, where N is the input length. When N is large, this matrix become massive, taking a huge space of HBM and making the inference slow.

The key insight of flash attention is that standard attention wastes memory and time by reading and saving the full N x N score matrix from and to HBM, but we can compute the exact same result of the attention layer block by block without ever needing the full score matrix. To make this work, we need a trick to update softmax update online.

Standard Attention Recap

Recall that standard attention computes:

R = Softmax(Q K^T / sqrt(d)) V

Here R is the output matrix. The problem is that computing the full Q K^T matrix requires O(N^2) memory where N is the sequence length. For long sequences, this intermediate matrix is enormous and must be read/written to slow GPU high-bandwidth memory (HBM).

The Hardware Process for standard attention:

  1. Read Q and K from HBM into Static Random-Access Memory (SRAM).
  2. Compute the pre-softmax scores S = Q K^T in SRAM.
  3. Write the massive N x N matrix S from SRAM to HBM.
  4. Read S from HBM back into SRAM.
  5. Compute the probabilities P = Softmax(S) in SRAM.
  6. Write the massive N x N matrix P from SRAM to HBM.
  7. Read P and V from HBM into SRAM.
  8. Compute the final output R = P V in SRAM.
  9. Write the final N x d output R to HBM.

Those four massive reads/writes of S and P takes O(N^2) memory and also most of the computing time (memory-bounded).

The FlashAttention Idea: Block-wise Computation

FlashAttention eliminates those intermediate O(N^2) reads and writes by processing the matrices in chunks (tiles). This ensures the intermediate matrices never leave SRAM.

The Hardware Process of FlashAttention:

  1. Initialize the final output matrix R in HBM.
  2. Outer Loop: Read a block of queries (Q_block) from HBM into SRAM. Reserve a corresponding block for its output (R_block) in SRAM.
  3. Inner Loop: For each corresponding block of keys and values in the sequence:
    • Read the key block (K_block) and value block (V_block) from HBM into SRAM.
    • Compute the partial attention scores S_block = Q_block K_block^T directly in SRAM.
    • Update the running softmax statistics using the online softmax trick, and compute the partial probabilities P_block entirely in SRAM.
    • Multiply P_block by V_block and mathematically accumulate the result into the waiting R_block.
    • Evict K_block and V_block from SRAM to free up space.
  4. Write the mathematically completed R_block from SRAM to HBM exactly once.
  5. Move to the next block of Q and repeat the process.

Note how in the Inner Loop above, all chunk of Q, K, V are read into SRAM from HBM only once, and then the corresponding chunk of R is returned to HBM.

Gradual computation of R_i

We now explain how FlashAttention works specifically. FlashAttention divides Q, K, and V into b small blocks, each containing t elements (queries, keys, or values):

Q = [Q_1, Q_2, ..., Q_b]      (b blocks of queries, each of size t)
K = [K_1, K_2, ..., K_b]      (b blocks of keys)
V = [V_1, V_2, ..., V_b]      (b blocks of values)

The output R can similarly be partitioned into blocks:

R = [R_1, R_2, ..., R_b]

The key point is that FlashAttention computes each output block R_1, R_2, ..., R_b separately, and within each output block, it builds the result gradually by streaming through the K and V blocks one at a time.

Taking R_1 as an example (all other R_i are updated similarly), FlashAttention computes it in b steps:

Step 1:  R_1^(1) = Softmax(Q_1 (K_1^T) / sqrt(d)) (V_1)

Step 2:  R_1^(2) = Softmax(Q_1 (K_1^T  K_2^T) / sqrt(d)) (V_1^T V_2^T)^T
                                                             
  ...

Step b:  R_1^(b) = Softmax(Q_1 (K_1^T ... K_b^T) / sqrt(d)) (V_1^T ... V_b^T)^T

After b steps, R_1^(b) = R_1, which is what we want in the end. The critical question here is how to update from R_1^(i) to R_1^(i+1) efficiently.

Update softmax attention online

Let us take one query from Q_1 as an example. Without loss of generality, denote it as q_1, and denote its output after step i as r_1^(i+1).

Expanding the output at step (i+1)

After processing through the (i+1)-th K and V blocks, the output for query q_1 is:

r_1^(i+1) = Softmax(q_1^T (K_1 ... K_(i+1)t) / sqrt(d)) (V_1^T, ... V_(i+1)^T)^T

Since the (i+1)-th step has seen keys from blocks 1 through (i+1) (a total of (i+1)t keys), and each block has t values, we can write this out explicitly:

                   exp(q_1^T k_j / sqrt(d) - s^(in))
r_1^(i+1) = SUM_j  ------------------------------------------  *  v_j
                   SUM_j' exp(q_1^T k_j' / sqrt(d) - s^(in))

Here s^(in) is the maximum of q_1^T k_j / sqrt(d) across all j in blocks 1...(i+1). This is the "max trick" subtracted for numerical stability (it does not change the result since it cancels in the softmax ratio, but prevents overflow in the exponentials).

We use v_j (small v) to denote the value corresponding to key k_j.

The decomposition

The key mathematical insight is that we can split the sum in both the numerator and denominator into two parts: the contribution from blocks 1...i (which we already computed) and the new contribution from block i+1:

         
             SUM_{j=1}^{it} exp(q_1^T k_j / sqrt(d) - s^(in)) v_j +  SUM_{j=it+1}^{(i+1)t} exp(q_1^T k_j / sqrt(d) - s^(in)) v_j
r_1^(i+1) = --------------------------------------------------------------------------------------------------------------------
                                SUM_{j=1}^{(i+1)t} exp(q_1^T k_j / sqrt(d) - s^(in))

This can be further rewritten by separating the two parts:

              SUM_{j=1}^{it} exp(q_1^T k_j/sqrt(d) - s^(i))
r_1^(i+1) =  ------------------------------------------------  *  [previous weighted sum]
              SUM_{j=1}^{(i+1)t} exp(q_1^T k_j/sqrt(d) - s^(in))

              SUM_{j=it+1}^{(i+1)t} exp(q_1^T k_j/sqrt(d) - s^(in))
           +  -------------------------------------------------------  *  [new block weighted sum]
              SUM_{j=1}^{(i+1)t} exp(q_1^T k_j/sqrt(d) - s^(in))
The second term depends only on block K_{i+1} and V_{i+1}. At each step, the running denominator sum can be updated incrementally, and the new block's contribution is computed fresh. This is what makes FlashAttention work without storing the full N x N attention matrix.

What Gets Updated at Each Step

At each step when processing a new K/V block, we maintain and update:

  • The running sum of exponentials (denominator): this accumulates across all blocks seen so far and can be updated by simply adding the new block's contribution (with appropriate rescaling when the running max changes)
  • The running weighted numerator: the sum of exp(score) * v terms, which is similarly updated by rescaling the old sum and adding the new block's terms
  • The running max s^(in): updated as the max of the old max and the new block's max, needed for numerical stability

Summary

During the above processes, we can see that

  • FlashAttention has the same computational time complexity as stanard attention (O(N^2)).
  • FlashAttention reduces the space (memory) complexity from O(N^2) to O(N) by avoding computing and storing the whole attention score matrix at once.
Although FlashAttention has the same computational complexity as standard attention, it is normally 2-4 x faster than standard attention. This is because it avoids move the attention score matrix back and forth between HBM and SRAM.
