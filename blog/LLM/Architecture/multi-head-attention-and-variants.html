Multi-Head Attention and Variants

LLM

A concise handwritten version of this note is available as a PDF.

Multi-head attention is the key component of every transformer, but during inference it can create a serious memory problem: the KV cache grows linearly with sequence length and scales with the number of heads. To alleviate such constraints, we can consider Grouped Query Attention (GQA).

Standard Multi-Head Attention

In standard Multi-Head Attention, the input X is projected into multiple independent sets of queries, keys, and values. Each set acts as a "head," and each head computes its own attention independently.

Intuition: The intuition behind Multi-Head Attention is that a single word representation can contain many different characteristics of the word (e.g., it could be a verb, it is in the past tense, and it has the semantic meaning of "play"). If we just used a single Scaled Dot-Product Attention layer, we would be forced to query all of these characteristics in one shot. Consequently, when we compute the softmax scores, a dominant trait like the verb characteristic might outweigh the past tense, causing the tense to be ignored. The Multi-Head Attention layer, however, allows the model to apply many different projections of the word representation into different subspaces. Each subspace focuses on a subset of the word's characteristics, so the first head might focus on the verb part, the second head could focus on the past tense, and so on. This would allow the output of the Multi-Head Attention to represent more information more easily.

Per-Head Projections

For each head i, we project the input through learned weight matrices:

Q^i = X * W_Q^i
K^i = X * W_K^i
V^i = X * W_V^i

Where W_Q^i, W_K^i, and W_V^i are the projection matrices for head i. Each head operates in a lower-dimensional subspace (typically d_model / num_heads).

Per-Head Attention Computation

Each head computes scaled dot-product attention independently:

C_i = softmax(Q^i * (K^i)^T / sqrt(d_k)) * V^i

Concatenation and Output Projection

The outputs of all heads are concatenated and passed through a final linear projection:

Output = [C_1, C_2, ..., C_h] * W_o

Where W_o is the output projection matrix and h is the total number of heads.

Each head independently learns to attend to different relationships in the data. One head might focus on syntactic dependencies, another on semantic similarity, and so on.

The KV Cache Bottleneck

During autoregressive inference (generating one token at a time), a critical optimization is the KV cache: at each head, the keys and values of all previous tokens are cached so they do not need to be recomputed at every step.

The problem is that this cache grows linearly with sequence length and scales with the number of heads:

  • Each head maintains its own separate K and V cache
  • Memory usage: 2 * num_heads * seq_len * d_k (factor of 2 for K and V)
  • For models with many heads (e.g., 32 or 64), this becomes a significant memory bottleneck during long-context inference
  • The cache gets longer and longer as more tokens are generated, eventually becoming the dominant memory cost

The KV cache is essential for efficient inference (avoiding quadratic recomputation), but its memory cost limits the batch size and maximum sequence length that can be served.

Solution: Grouped Query Attention (GQA)

Grouped Query Attention (introduced by Ainslie et al., 2023) provides a solution to the KV cache bottleneck. The core idea is divide the query heads into groups. Each group of query heads shares a single key head and a single value head. Intuition behind the idea: having multiple different query is more important than having multiple different key and value. When researchers analyzed standard Multi-Head Attention, they found that many of the Key and Value heads were practically identical. The model was learning the same representations multiple times.

How GQA Works

Instead of having h independent K and V projections (one per query head), GQA uses only g groups of K/V pairs, where g < h. Multiple query heads within the same group share the same K and V:

For group j (containing query heads i_1, i_2, ..., i_n):

  K^j = X * W_K^j       (shared key for the group)
  V^j = X * W_V^j       (shared value for the group)

  Q^(i_1) = X * W_Q^(i_1)   (each query head still has its own projection)
  Q^(i_2) = X * W_Q^(i_2)
  ...

  C^(i_1) = softmax(Q^(i_1) * (K^j)^T / sqrt(d_k)) * V^j
  C^(i_2) = softmax(Q^(i_2) * (K^j)^T / sqrt(d_k)) * V^j
  ...

The final output is still the concatenation of all head outputs projected through W_o:

Output = [C^(1,1), ..., C^(1,n), C^(2,1), ..., C^(g,n)] * W_o

Memory Savings

The KV cache reduction is proportional to the grouping factor. If we have h heads and g groups:

  • Standard MHA: KV cache size = 2 * h * seq_len * d_k
  • GQA: KV cache size = 2 * g * seq_len * d_k
  • Reduction factor: h / g

For example, with 32 query heads and 8 KV groups, the KV cache is reduced by 4x.

Special Cases

GQA is a generalization that includes two extremes:

  • When g = h (one group per head): This is standard Multi-Head Attention — every query head has its own K and V.
  • When g = 1 (one group for all heads): This is Multi-Query Attention (MQA, Shazeer 2019) — all query heads share a single K and V, giving the maximum cache reduction but potentially sacrificing quality.

GQA strikes a balance between MHA (full quality, large cache) and MQA (minimal cache, potential quality loss). In practice, models like LLaMA 2 70B use GQA with 8 KV heads for 64 query heads.

Summary

  • Standard MHA: Each head has independent Q, K, V projections. Powerful but memory-intensive at inference due to per-head KV caching.
  • KV Cache Bottleneck: During autoregressive generation, caching K and V for all heads across all past tokens dominates memory usage.
  • GQA: Groups query heads to share K/V, reducing cache by a factor of h/g while retaining most of MHA's representational power.
