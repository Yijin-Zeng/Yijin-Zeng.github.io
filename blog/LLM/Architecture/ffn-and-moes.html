FFN and Mixture of Experts

LLM

A concise handwritten version of this note is available as a PDF.

The idea behind Mixture of Experts is simple and powerful: instead of one large FFN that every token passes through, have many smaller "expert" FFNs and a learned router that picks which ones to use for each token. This gives the model more parameters (capacity) without proportionally increasing compute.

Background: The FFN in a Transformer Block

A standard Transformer block consists of two sub-layers: an attention layer followed by a feed-forward network (FFN). The FFN is applied independently to each token position and typically consists of two linear transformations with a nonlinear activation in between:

FFN(x) = W2 * activation(W1 * x + b1) + b2

For example, if d_model = 4096, the FFN typically expands the dimension by a factor of 4 in the first layer (to 16384) and projects it back down in the second layer (back to 4096). The activation function is commonly GELU or SiLU in modern architectures.

Mixture of Experts (MoE): The Core Idea

In a standard Transformer, every token passes through the same FFN. In a Mixture of Experts model, the single FFN is replaced by multiple FFN "experts" and a learned router that decides which experts each token should be sent to. This allows the model to have many more parameters (and thus more capacity) while only activating a small subset of them for any given token.

Key point: MoE replaces the FFN layer (not the attention layer) in the Transformer block. The attention layer remains unchanged.

Architecture Overview

The overall Transformer still has ~N layers stacked on top of each other, where each layer contains an attention sub-layer and a FFN sub-layer. In the MoE variant, some or all of the FFN sub-layers are replaced by the MoE module:

The Router

The router is the mechanism that decides which experts handle each token. It is a simple learned linear projection from the token representation to a score for each expert:

router_logits = Softmax(x * W_R)    where W_R has shape (d_model, num_experts)

The input x here is the output of the attention layer. For example, with a sequence of 300 tokens and d_model = 4096, the input shape would be (300, 4096), and the router produces scores of shape (300, num_experts), one score per expert for each token.

Top-K Selection

The router assigns a score to each expert, but we do not activate all of them. Instead, we pick the top-K experts (typically K=2) for each token:

  • Compute router scores for all experts
  • Select the top-K scores (e.g., top-2)
  • Zero out all other scores
  • Renormalize the remaining K scores so they sum to 1 (i.e., S_1 + S_2 = 1)

Only two experts are activated per token. This is what makes MoE "sparse". Despite having many experts, only a small subset does computation for any given token.

Combining Expert Outputs

Once the top-K experts have processed the token, their outputs are combined via a weighted sum using the normalized router scores:

output = S_1 * y_1 + S_2 * y_2

where:
  S_1, S_2 = normalized routing scores (S_1 + S_2 = 1)
  y_1, y_2 = outputs from the two selected experts

The Experts

Each expert is structurally identical to a standard FFN: two linear layers with a nonlinear activation in between. They all share the same architecture and are normally initialized the same way at the start of training, but they diverge and specialize as training progresses.

Expert_i(x) = W2_i * GELU(W1_i * x)

Dimensions (example):
  First layer:  4096 -> 4096*k (expand)
  Second layer: 4096*k -> 4096 (project back)

The key difference from a standard Transformer is that instead of one large FFN shared across all tokens, there are many smaller experts, and each token only uses a few of them. This dramatically increases the total parameter count while keeping the per-token compute roughly constant.

How the Router Gets Trained

A natural question is: how do gradients flow through the top-K selection, which is a discrete operation? The approach used in practice introduces a constant mask matrix. Conceptually:

scores = Softmax(x * W_R * M_mask)

The mask M_mask is derived from the top-K selection and applied to allow gradients to flow back through the softmax to the router weights W_R. Since the softmax and the linear projection are both differentiable, the router weights get updated via standard backpropagation. The top-K selection itself is handled by zeroing out non-selected logits before the softmax (or equivalently, setting them to negative infinity), which means the gradient with respect to those positions is zero, while the gradient flows normally through the selected positions.

Implementation

Below is a PyTorch implementation that illustrates the full MoE mechanism. It includes an individual expert FFN class and the sparse MoE layer with routing logic:

Expert FFN

import torch
import torch.nn as nn
import torch.nn.functional as F

class ExpertFFN(nn.Module):
    """A standard Feed-Forward Network acting as an individual expert."""
    def __init__(self, d_model, d_hidden):
        super().__init__()
        self.fc1 = nn.Linear(d_model, d_hidden)
        self.fc2 = nn.Linear(d_hidden, d_model)
        self.act = nn.GELU()

    def forward(self, x):
        # Example: 4096 -> 16384 -> 4096
        return self.fc2(self.act(self.fc1(x)))

Sparse MoE Layer

class SparseMoE(nn.Module):
    def __init__(self, d_model, num_experts, top_k, d_hidden):
        super().__init__()
        self.num_experts = num_experts
        self.top_k = top_k

        # The Router Matrix (W_R)
        self.router = nn.Linear(d_model, num_experts, bias=False)

        # The N Experts
        self.experts = nn.ModuleList([
            ExpertFFN(d_model, d_hidden) for _ in range(num_experts)
        ])

    def forward(self, x):
        batch_size, seq_len, d_model = x.shape
        # Flatten batch and sequence dimensions: N = batch_size * seq_len
        x_flat = x.view(-1, d_model)

        # 1. Calculate router logits for the entire flattened batch
        # Shape: (N, num_experts)
        router_logits = self.router(x_flat)

        # 2. Dynamic Masking / Top-K Selection
        # PyTorch's topk extracts the highest scores;
        # softmax only on those is mathematically identical
        # to masking with -inf and doing full softmax.
        topk_logits, topk_indices = torch.topk(
            router_logits, self.top_k, dim=-1
        )

        # Softmax over only the Top-K choices so they sum to 1
        # Shape: (N, top_k)
        topk_weights = F.softmax(topk_logits, dim=-1)

        # 3. Dispatching to Experts
        final_output = torch.zeros_like(x_flat)

        for i in range(self.top_k):
            expert_indices = topk_indices[:, i]        # Shape: (N,)
            weights = topk_weights[:, i].unsqueeze(1)  # Shape: (N, 1)

            for expert_idx in range(self.num_experts):
                # Boolean mask: which tokens go to this expert
                token_mask = (expert_indices == expert_idx)

                if not token_mask.any():
                    continue

                # Extract tokens for this expert
                expert_input = x_flat[token_mask]

                # Run through expert
                expert_output = self.experts[expert_idx](expert_input)

                # Weight by routing probability: S_i * y_i
                weighted_output = expert_output * weights[token_mask]

                # Accumulate
                final_output[token_mask] += weighted_output

        # Reshape back to (batch_size, seq_len, d_model)
        return final_output.view(batch_size, seq_len, d_model)
