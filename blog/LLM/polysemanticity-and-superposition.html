Polysemanticity and Superposition

LLM

A concise handwritten version of this note is available as a PDF.

One of the most surprising things about LLM is that individual neurons often 'fires' (activates) for multiple semantically completely unrelated concepts such as hot chocolate and JAVA's closing brackets. This phenomenon is known as polysemanticity, and the superposition hypothesis offers a plausiable explanation.

1. What Is Polysemanticity?

Polysemanticity is the phenomenon where a single neuron activates (i.e. outputs a value much larger than other neuron's, more in below) for multiple, semantically unrelated concepts.

In an ideal world, we would have monosemanticity: each neuron corresponds to exactly one concept. For example:

  • Neuron #52 activates only for "cats"
  • Neuron #900 activates only for "syntax errors"

In reality, neuron #52 might activate for:

  1. Cats
  2. Snow
  3. Embedded closing brackets in Python code

These concepts are completely unrelated to each other, yet the same neuron fires for all of them.

What does "activated" mean?

When we say a neuron is "activated," we mean it produces a large output value. For example, it probably gives a value 16.2, where all other neurons outputs values around 0. There are two types of neuron can be activated. More often, we are saying the neurons in the feed forward layer. In a decoder-only transformer, since the input is a sequence, we only care about the output for the last token of the sequence. We say a neuron is activated when its output value for the last token of the sequence is large. Another type of neuron can be activated is in attention layer. The output of the attention layer is a linear combination across heads:

Output = Output_head_1 + ... + Output_head_n

If ||Output_head_i|| is large, then we say that head i is activated. Since we only care about the final output, what matters is whether the last token has large components.

2. How the MLP Works in a Transformer (Decoder Only)

To understand polysemanticity better, I find it helps (at least for me) to understand the role of the MLP layers in a transformer. I always understood the role of MLP layers as simple as 'adding more non-linear transformations' to transformer. However, it turns out that the MLP is much more important than this.

In short, attention layers aggregate information so far to the embedding of the last token, and then send this embedding as a "query" to the MLP, which then "reasons" about what to add for next word prediction.

The architecture looks like this:

Contextual embedding       MLP Layer 1        MLP Layer 2         Output
of last token               (expand)           (contract)
from transformer block

     X([size 4096]) ----> [dimension 16384] --> [dimension 4096] -----> Output([size 4096])-->
     |                                                                   |
     |_____________________ residual connection _________________________|

Observations about this architecture:

  • The input (size 4096) acts as a query: "what information should be added for next word prediction?" (because we have residual connections)
  • The first MLP layer as a key. Notice that it normally is 4 times of the model dimension (e.g., from 4096 to 16384). This upscale gives more room to represent the semantic meaning. Consider each dimension might represent different semantic meaning, e.g. French, chocolate etc. However, 16384 is probably still not big enough to represent all possible meanings.
  • The second MLP layer acts as a value. It acts like a knowledge pool, determining what we want to add into the final token's embedding once we know what semantic meanings the embedding is looking (after key and query).
  • The residual connection means the MLP layers learn to add information to the original contextual embedding, not replace it.

Where polysemanticity appears in the MLP

The contextual embedding of the last token from the transformer block can be expressed as a linear combination of neuron activations:

e.g., french = a_1 * neuron_1 + a_2 * neuron_2 + ... + a_n * neuron_n

Each column in the weight matrix is an independent vector (they form basis vectors in the vector space). Say a_1, a_2, a_3 >> 0 while other a_i ≈ 0 or are small. Then neurons 1, 2, 3 will "fire" (give large outputs) if the query is looking for "French."

This is where polysemanticity happens. We might observe super large values for certain neurons in the expanded 16384-dimensional vector. Since this vector now represents how much information we need for each feature, it becomes mathematically impossible for one neuron to represent only one meaning -- this would require monosemanticity, but the model needs to cram many more concepts into the available neurons.

How does the model handle polysemantic neurons correctly?

Since one neuron might represent different concepts, how does the model aggregate the information correctly? For example, if some of the neurons that fire for "French" also fire for "Java," how does the model avoid confusing itself?

Since multiple neurons fire for "French," their combination in the value weights (the 16384-sized output matrix) adds up to "French." Meanwhile, "Java" has a different set of neurons fire, although some individual neurons may overlap with "French." The overall pattern of activation is what distinguishes concepts, not any single neuron.

3. Why Does Polysemanticity Happen?

The Superposition Hypothesis

According to superposition hypothesis, the root cause for polysemanticity is

d_features >> d_model

Where:

  • d_features = the number of distinct features/concepts the model needs to represent
  • d_model = the dimension of the model output (e.g., 16384), which equals the maximum number of orthogonal vectors in the space

Under the superposition hypothesis, a single concept has to be represented as a linear combination of multiple neurons, because there is simply not enough room to represent all semantically independent concepts orthogonally. The math is simple, a 16384 dimensional space can have at most 16384 independent vectors.

If d_features < d_model, then it would be possible to present each feature as a one-hot-like vector (e.g., (1,0,0,0,...), (0,1,0,...)), achieving monosemanticity. Even if the representation is not axis-aligned, we can simply rotate them (e.g., via PCA). For instance, (0.7, 0.7) perpendicular to (-0.5, 0.5) can be rotated to align with axes.

Note however, in high-dimensional space, the number of nearly orthogonal vectors grows exponentially with dimension. Vectors can have dot products as small as 0.01 and still be "almost orthogonal" -- this is related to the Johnson-Lindenstrauss Lemma.

4. More About Polysemanticity and Sparse Autoencoders

We can explain the above more formally. Say for one layer, there are some concepts we want to activate. The "gold view" is a vector h in R^(d_features x 1) that would be super sparse:

h = [0, 0, 0, ..., 1, 0, ..., 0, 0, ..., 0]   (mostly zeros, a few non-zero entries, e.g. for Paris, French)

What we actually have in the model is:

x = X_model * h

Where x is the model output (the contextual embedding of the last word) we can observe, X_model is in R^(n x d) with n << d, and h represents the concepts we want to use for the contextual embedding. However, the problem is that we only have n neurons to represent the concept, far fewer than the d features.

Consequences of this compression:

  • x_i (individual neuron activations) are not independent, even if two concepts should be semantically independent
  • One neuron may fire for independent concepts

In practice, we observe x in the model, and we want to know h (the underlying sparse concept vector):

h = X_model^+ * x

Where X_model^+ is the pseudo-inverse. It is not easy to learn h from the embedding directly, because the firing neurons corresponding to different concepts might overlap. For example, consider the following three concepts and their assumed firing neurons: "Paris" = Neurons 1, 4, and 7 "Food" = Neurons 4, 7, and 9 "France" = Neurons 1, 7, and 9 Neurons 1, 4, 7, and 9 firing simultaneously, how do we know it's the combination of "Paris" + "Food", or "Paris" + "France"? We learn h through a Sparse Autoencoder (SAE).

How SAEs work

A Sparse Autoencoder is trained to recover the sparse concept vector from the model's activations:

Input: x --> f_e(x) --> g_d(e) --> x*

        Where:
        f_e = encoder: projects x to a sparse embedding (with n_features >> d_model)
        g_d = decoder: reconstructs x from the sparse embedding

        Loss = reconstruction error (||x - x*||) + L1 loss on the embedding layer (to enforce sparsity)

After we learn the SAE, we can use it to interpret the model: pass a sentence with a concept close to "Paris" through the model, observe which components in the sparse embedding layer are activated, and the next time we see those components activated, we know the concept "Paris" is being represented. The key for the success of SAE lies in the fact that n_features >> d_model, so the embedding space in SAE has much more room to represent different concepts.

5. Why Is Polysemanticity Bad?

So polysemanticity might sound a bit weird, but why it is a bad thing for LLM?

Problem 1: Cannot control model behavior

If we had monosemanticity, we could:

  1. Find the neuron generating harmful content and turn it off (always output small values, so the related concept can never be outputed)
  2. Find the neuron corresponding to "safety" and increase its weight, making the model generate more safety-related concepts. For example, if we increase the weight a lot, the model might produce nonsense like: "Safety is important, safety, security, safety, safety..."

But with polysemanticity, increasing the weight of a "safety" neuron might also amplify other concepts sharing that neuron. This could lead to things undesirable, especially if we dont know what other concepts might be.

Problem 2: Cannot monitor the model's behavior

If we had monosemanticity, we could monitor the internal state of the model and roughly know what the model is going to output -- without needing to see the actual input and output. This would be incredibly valuable for AI safety: we could detect when a model is "thinking about" harmful topics before it produces any output.

With polysemanticity, internal monitoring becomes much harder because each neuron's activation is ambiguous. It could mean any of several unrelated things.
