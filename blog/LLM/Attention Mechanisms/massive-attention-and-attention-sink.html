Massive Activations and Attention Sink

LLM

A concise handwritten version of this note is available as a PDF.

These are two related phenomena that I find fascinating because they reveal how transformers "hack" their own architecture. Massive activations are neurons that always fire at extreme magnitudes regardless of input, and attention sink is where the model dumps attention onto the meaningless first token. Both are emergent strategies, not bugs.

Massive Activations

Massive activations refer to a small number of specific neurons that consistently output values that are orders of magnitude (100x or 1000x) larger than all other neurons in the network.

Key characteristics

  • Mostly observed in dense (feed-forward) layers
  • Tend to appear in specific feature dimensions
  • Stay massive regardless of the input text — they fire at extreme magnitudes no matter what sequence is being processed

Problem: quantization difficulty

Massive activations create significant challenges for model compression, particularly quantization. Consider what happens when we quantize to INT8 (8-bit integers), which maps all floating-point numbers to the range 0–255.

Say we have a weight vector with values like:

[0.01, 0.2, ..., 1000.02]

To store the outlier value of 1000.02 within the quantized range, the smaller values like 0.01 get squeezed down toward 0. This dramatically reduces the effective precision for the majority of weights, decreasing model accuracy.

The core tension is this: a single massive value forces the entire quantization range to stretch, compressing all normal-magnitude values into a tiny portion of the available bit range. You lose precision everywhere just to accommodate a handful of outliers.

Solution: compress them separately

Since massive activations are few in number and appear at fixed feature dimensions, we can handle them with a separate quantization scheme (e.g., keep them in higher precision like FP16) while quantizing the remaining activations normally. This preserves accuracy without sacrificing compression ratio significantly.

Possible explanation: implicit bias terms

One hypothesis is that massive activations act as bias terms that shift the model's internal focus. In a linear transformation Ax + b, the bias b shifts the output regardless of input. Similarly, these always-on massive activations may serve as learned constant offsets that the model uses to establish baseline attention patterns or feature representations, independent of the specific input being processed.

Attention Sink

Attention sink refers to a phenomenon where the model allocates a massive amount of attention to the very first token (typically <sos> or <bos>), even though this token has no semantic meaning for the current context.

This has been consistently observed across many transformer-based language models. The initial token accumulates disproportionate attention weight across layers, acting as a "sink" that absorbs attention that has nowhere else meaningful to go.

Problem: streaming LLM with sliding window

Consider a streaming LLM scenario where we want the model to process an infinite length of text. A natural approach is to use a sliding window strategy for the KV cache, since the computational cost of full attention is O(n^2) for paying attention to all previous tokens.

Full attention:    [t1, t2, t3, ..., tn] -- O(n^2) cost
Sliding window:   [..., t_{i-w}, ..., t_i] -- O(w) cost per step

However, this strategy will fail because as the window slides forward, it eventually drops the <sos> token from the cache. Since other tokens often pay a large amount of attention to <sos>, removing it destabilizes the model's attention distribution and degrades generation quality significantly.

Solution: keep the first few tokens

The fix is straightforward: always keep the first few tokens (including <sos>) in the KV cache while sliding the rest of the window. This is the approach taken by StreamingLLM:

StreamingLLM cache: [t1, t2, ..., t_k] + [t_{i-w}, ..., t_i]
                     ^^^^^^^^^^^^^^^^     ^^^^^^^^^^^^^^^^^^^
                     always kept (sink)   sliding window

By retaining these "attention sink" tokens, the model maintains stable attention patterns even over very long sequences, enabling true streaming inference without quality degradation.

Possible explanation: attention dumping

Why does attention sink happen? When a token does not need to pay much attention to other tokens (i.e., it already has enough context or the current position is relatively self-contained), it needs somewhere to "dump" the remaining attention probability mass. The <sos> token serves as a convenient target because it is a common token present in all sequences — every input starts with it, so the model learns early in training that it is always available as a safe default target.

The attention sink is not a bug but an emergent strategy: the model learns to use a universally-present token as a no-op attention target when it has no useful information to attend to. I think this is one of those findings that makes you appreciate how resourceful gradient descent really is.

Connection Between the Two

Massive activations and attention sink are related phenomena. Both involve the model concentrating extreme values in specific, fixed locations:

  • Massive activations: extreme values in fixed feature dimensions of hidden states
  • Attention sink: extreme attention weights on fixed positional tokens

Both can be understood as the model's way of encoding global, input-independent information (biases, default behaviors) within an architecture that does not explicitly provide separate mechanisms for such signals.
