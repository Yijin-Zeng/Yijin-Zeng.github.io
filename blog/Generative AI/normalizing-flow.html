Normalizing Flow

Generative AI

A concise handwritten version of this note is available as a PDF.

Normalizing flow is a generative model that tries to learn the distribution of the data directly. Like other generative models, it starts from something simple — a standard normal z ~ N(0, I) — and pushes it through a generator f(z; φ) to produce a complex, targeted distribution over x:

z ~ N(0, I)  -->  generator f(z; φ)  -->  x

   standard normal          complex, targeted
       ___                   distribution p(x)
      /   \        f(·)        _      _
     /     \      ----->      / \    / \
    /       \                /   \__/   \

Denote the resulting density pr(x|φ). If we knew pr(x|φ), training would be simple — just maximize the likelihood of real images:

φ̂ = argmax_φ  Σ_{i ∈ real images} log pr(x_i | φ)

So the question is: if we know f(·), can we know p(x)? Generally not — for an arbitrary neural network the induced density has no closed form. But if f is invertible, then yes.

The Hard Part: What Is pr(x|φ)?

The tool we need is just integration by substitution, the same one from calculus. Suppose X ~ F(x) and Y = φ(X) where φ is invertible. What distribution does Y follow?

Pr(Y ∈ R) = Pr(X ∈ φ⁻¹(R))
          = ∫_{φ⁻¹(R)} f_X(x) dx
          = ∫_R f_X(φ⁻¹(y)) |dφ⁻¹(y)/dy| dy     ← changing variable from x to y

So the density of Y is the density of X evaluated at the pre-image, times the absolute value of the determinant of the Jacobian of the inverse map. Applying this to our generator (base density is standard normal):

pr(x|φ) = N( f⁻¹(x; φ); 0, I ) · |det( ∂f⁻¹(x)/∂x )|
        = N( z; 0, I ) · |det( ∂f(z)/∂z )|⁻¹     where f(z; φ) = x

The second line uses the inverse function theorem: the Jacobian of the inverse is the inverse of the Jacobian, so its determinant is the reciprocal.

So in order to evaluate the likelihood, the generator f(z; φ) must be invertible. And not just in theory — we should also be able to invert it and compute the determinant of its Jacobian efficiently. For a general invertible matrix, the determinant is an O(n³) operation, which is not feasible for image-sized dimensions.

The network runs in both directions, and each direction has a different job: the inverse mapping evaluates the likelihood of real samples during training, and the forward mapping turns noise into samples during generation.

  <---- inverse mapping: evaluate likelihood of real samples (training)

z  <-->  [ generator f(z; φ) ]  <-->  real samples x

  ----> forward mapping: transform noise into samples (generation)

Designing Invertible Layers

This is the key in normalizing flow. We want layers with three properties:

  • Expressive — sufficiently expressive to approximate any function.
  • Invertible — otherwise the change of variables formula doesn't apply.
  • Practical — we can invert it and evaluate the Jacobian determinant efficiently.

The basic building blocks are linear flows and element-wise flows. Individually they satisfy properties 2 and 3 but fail 1 — but they are the basis for more sophisticated layers that satisfy all three.

Linear Flows

The simplest candidate: Y = ΩX + β. If Ω is invertible, the layer is invertible. But how do we guarantee Ω stays invertible during training, and keep the determinant cheap? The trick is to parameterize Ω in PLU form:

Ω = P L U

P: permutation matrix (fixed during training)
L: lower triangular, diagonal fixed to 1
U: upper triangular, diagonal set to s_i = sign(s_i) · exp(α_i)

The diagonal of U is the only place invertibility can fail, so we force it non-zero by construction: sign(s_i) is fixed at the beginning, and we train α_i (initialized as log|s_i|). Since exp(α_i) > 0 always, the determinant can never hit zero — the constraint is handled by the parameterization itself rather than enforced during optimization.

Initialization is also thoughtful:

  1. Generate a random orthogonal matrix (sample a random matrix, run QR decomposition). Its determinant is 1, which stabilizes training at the beginning.
  2. Run PLU decomposition on it.
  3. Set Ω = PLU, replacing the diagonal of U with the sign(s_i) · exp(log|s_i|) parameterization.

Now everything we need is cheap. The Jacobian is just Ω itself, and:

|det(∂Y/∂X)| = |det(Ω)| = |det(P)| · |det(L)| · |det(U)|
             = (±1) · 1 · Π_i sign(s_i) exp(α_i)     ← product of diagonals

Inversion is also easy — no matrix inverse needed, just two rounds of back substitution:

Y = ΩX + β  =>  LUX = Pᵀ(Y - β)
solve  Lz = Pᵀ(Y - β)   then   Ux = z      ← both O(n²)

Problem of linear flow: it is only linear. If we stack only linear flows, we can only ever get linear combinations of the input (a composition of linear maps is still linear). So we need a non-linear part.

Element-wise Flows

Apply an invertible non-linear function to each coordinate independently: y_i = f(x_i; φ), e.g. leaky ReLU or the exponential function. The Jacobian is diagonal, so its determinant is trivial:

|det(J)| = Π_{i=1}^{D} |∂f(x_i)/∂x_i|

And the inverse is simple as long as f⁻¹ is simple. Problem of element-wise flow: it is non-linear but does not mix features — each dimension lives in its own world. So it is natural to alternate the two:

input --> [ linear flow --> element-wise flow ] --> ... --> [ block ] --> output
                       one block

Coupling Flows

This is the cleverer construction that modern flows (RealNVP, Glow) are built on. Split the input x into two halves, x₁ and x₂:

y₁ = x₁                          ← simply copy x₁
y₂ = f(x₂; φ(x₁))                ← element-wise flow, parameters
                                    determined by x₁

Note that φ does not need to be invertible — it can be an arbitrary neural network. Only the element-wise map f acting on x₂ needs to be invertible, because at inversion time we already know x₁:

x₁ = y₁
x₂ = f⁻¹(y₂; φ(x₁))

So we can smuggle unlimited expressive power into φ for free. The Jacobian is block-triangular (since y₁ doesn't depend on x₂), so:

| ∂y₁/∂x₁  ∂y₁/∂x₂ |   | I        0       |
|                   | = |                  |  =>  det = |∂y₂/∂x₂|
| ∂y₂/∂x₁  ∂y₂/∂x₂ |   | ∂y₂/∂x₁  ∂y₂/∂x₂ |

i.e. only the element-wise part contributes to the determinant, no matter how monstrous φ is. Permute which half gets copied across layers, and every dimension eventually gets transformed.

Two Directions of KL: Which Way Are You Fitting?

The last part of the note is about what objective we are actually optimizing, and it depends on which of two problems you have.

Standard normalizing flow: the target distribution q (real images) is easy to sample from but hard to evaluate. We minimize the forward KL, KL(q ‖ p_φ):

argmin_φ KL(q‖p_φ) = argmin_φ ∫ q(x) log[q(x)/p_φ(x)] dx
                   = argmax_φ ∫ q(x) log p_φ(x) dx        (q terms don't depend on φ)
                   = argmax_φ E_{x~q}[ log p_φ(x) ]
                   ≈ argmax_φ (1/n) Σ_i log p_φ(x_i)      => maximum likelihood

So the maximum likelihood training we started with is exactly forward KL minimization, with the expectation over q replaced by an average over real samples.

Reverse KL: the opposite situation. Suppose we have a distribution q we can evaluate easily but is hard to sample from — think unnormalized posteriors in Bayesian inference — and we want to approximate it with a flow so we can sample. Now we minimize KL(p_φ ‖ q):

argmin_φ KL(p_φ‖q) = argmin_φ { E_{x~p_φ}[log p_φ(x)] - E_{x~p_φ}[log q(x)] }
                              \____ negative entropy ____/
                   ≈ argmin_φ { (1/n) Σ log p_φ(x̂_i) - (1/n) Σ log q(x̂_i) }
                                              where x̂_i sampled from our model

So why not just maximize E[log q(x̂)] directly and skip the entropy term, since we can evaluate q easily? Because that would make all samples collapse to the mode of q — the single highest-density point. The entropy term is what prevents this from happening; it forces the model to keep spreading out.

Notice we still need to evaluate log p_φ(x̂_i), like in the standard flow — but since we generated x̂_i ourselves, we already know its z_i, so we don't need to invert the network. One subtle caveat from the note: consider the Box transformation for why we cannot just maximize the likelihood of transformed data — we must maximize the likelihood of the observations themselves, with the Jacobian correction included, otherwise the objective is meaningless (you could inflate the "likelihood" arbitrarily by squeezing everything to a point).

Summary

  • Normalizing flow learns p(x) directly and exactly, by pushing a simple base distribution through an invertible generator.
  • The price: the generator must be invertible, with a cheap inverse and a cheap Jacobian determinant.
  • Linear flows (PLU-parameterized) mix features; element-wise flows add non-linearity; coupling flows get arbitrary neural network expressiveness while keeping the determinant a simple diagonal product.
  • Maximum likelihood training is forward KL; reverse KL turns flows into samplers for densities you can evaluate but not sample — with the entropy term guarding against mode collapse.
