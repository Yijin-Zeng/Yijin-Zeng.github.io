RLHF: Reinforcement Learning from Human Feedback

LLM

A concise handwritten version of this note is available as a PDF.

RLHF is what takes a language model from "can complete text" to "can follow instructions well." The full pipeline has three stages, and I find it interesting how each stage addresses a specific limitation of the previous one.

Starting Point: Pre-training and SFT

Normally we start with a pre-trained language model. After pre-training, the model only learns to complete text -- it predicts the next token given a context. This is fundamentally different from answering a question. For example, given a question as input, the model might generate another question as a continuation, because that is what "completing text" looks like.

To bridge this gap, we apply Supervised Fine-Tuning (SFT): we take high-quality data and fine-tune the model on it. If we are building a chatbot, we prepare training samples in a question-answer (Q-A) format. This teaches the model to respond to prompts rather than simply continue text.

So after SFT, the model can answer questions -- but it still does not know what a "good" answer looks like from a human perspective. That is where RLHF comes in.

Stage 1: Training a Reward Model (Using Human Feedback)

The goal of this stage is to build a scalar reward function that can score any output from the LLM. We denote the reward model as r_θ. It is usually initialized from a fine-tuned LLM (often the same model after SFT).

The Process

We feed a prompt into the fine-tuned model and generate multiple candidate answers. For example, given a prompt, the model produces answers A, B, and C. Human annotators then rank these answers by quality (e.g., A > B > C).

                          +--> Answer A --|
                          |               |
Prompt --> Fine-tuned LLM +--> Answer B --|---> Ranked by humans (e.g. A > B > C)
                          |               |
                          +--> Answer C --|

The Loss Function

For each pair of responses where one is preferred over the other (e.g., A is preferred over B), the reward model is trained using a pairwise loss:

Loss = -log(r_θ(A) - r_θ(B))

More precisely, this is the negative log-sigmoid of the difference in scores, encouraging the reward model to assign a higher score to the preferred response. This is known as the Bradley-Terry model for pairwise comparisons.

After training the reward model, we can evaluate the output of any answer given by the LLM (e.g., score it 4.2). But here is the thing -- we cannot directly use this score to tune the model because backpropagation through a discrete sampling step is not possible. It is quite surprising to me that this is where RL becomes necessary: the reward signal exists but there is no differentiable path from it back to the model weights, so we have to treat the whole thing as a policy optimization problem.

Stage 2: Proximal Policy Optimization (PPO)

Now we use the reward model to actually improve the language model's policy via RL. This stage introduces two additional models on top of the policy (the LLM being trained):

  • Score model (reward model r_θ) -- the frozen reward model from Stage 1 that scores outputs
  • Value model -- estimates the expected score of the LLM's output; normally initialized as a copy of the model after SFT

The Process

                                    +---> Score model ---> a score (frozen at this stage)
                                    |
Prompt ---> Model ---> Output ------+
                                    |
                                    +---> Value model ---> estimated score (updated)

The decision logic at each step:

  • If score > estimated_score: the output was better than expected, so increase the probability of that output
  • Otherwise: decrease the probability of that output

The Advantage

The key signal for the policy update is the advantage:

A = advantage = score - estimated_score

This tells us how much better (or worse) the actual output was compared to what we expected. A positive advantage means "do more of this"; a negative advantage means "do less of this."

Vanilla Policy Gradient

The simplest approach: compute the gradient of the log-probability of the output (treating the answer as correct), then update the weights:

weights = weights - δ * gradients

Where δ is proportional to the advantage:

  • If A > 0: increase the probability of this output
  • If A < 0: decrease the probability of this output

The Problem with Vanilla Policy Gradient

The gradient can change the weights too much in a single step. This leads to catastrophic forgetting -- the model may collapse or lose previously learned capabilities after a large update.

PPO: Clipped Policy Gradient

PPO solves this by clipping the gradient of the policy gradient descent. The central concept is the probability ratio for a token w:

r = prob(w after updating according to policy gradient) / prob(w before updating)

PPO constrains this ratio to stay within a small band around 1:

1 - ε < r < 1 + ε

Typically ε = 0.2, meaning the probability of any token can change by at most 20% in either direction per update. This ensures the model improves steadily without making destructive jumps.

The name says it all: PPO keeps the updated policy "proximal" (close) to the old policy. Small, stable steps prevent catastrophic forgetting while still allowing the model to learn from the reward signal. Without the clipping, the model can collapse after a single bad update.

Summary: The Full RLHF Pipeline

  1. Pre-training -- learn general text completion from a large corpus
  2. SFT -- fine-tune on high-quality Q-A data to learn the instruction-following format
  3. Reward Model Training -- collect human rankings, train a model to score outputs
  4. PPO -- use the reward model to guide policy updates, with clipping to ensure stability
